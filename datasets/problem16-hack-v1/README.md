# 可复现 hack image / hack LUT 子集 v1

本子集根据 hack image/LUT Discussion 补充可解释压力输入，独立于 [corpus-v1](../problem16-v1/README.md)。不改旧 case、历史阈值、7,917 项计划或已发生的失败。本轮范围是数据构造、回放与阶段性核对，不批准或启动全面拟合、全色域精度及性能扫描。

[catalog.json](catalog.json) 冻结 **21 个开发 case、5 个预留验收 case**；每个 case 都是四张字节不同的合法 RGB8 完整 LUT。种子和算子参数显式保存，除随机表和图像重排外，算子由固定整数公式确定。[sources.json](sources.json) 保存去重后的每张完整源表 SHA-256；这些哈希由流式生成全部源字节得到，完整二进制表不重复纳入版本库，可按单 case 导出。

| 家族 | 本轮内容 | 解释范围 |
| --- | --- | --- |
| 可解释基线 | 反相抵消的恒等链、通道置换、反相、整数 gamma² 曲线、平滑 CCM | 核对坐标顺序、逐级量化及基本参考行为；不是自然照片表现承诺 |
| 裁剪与阶梯 | 高光硬裁剪、阈值 127/128/129、17 阶量化 | 阈值横跨 m17/m33 中央浮点节点 127.5 附近的整数码值；观察边界偏差 |
| 内部窄峰/窄谷 | R 从 122 开始，宽 1/2/4；G 上加 96，另有宽 2 的减 96 窄谷 | 位于两种均匀网格的相邻采样位置之间；属于局部表达与漏采样边界研究 |
| 跨通道 | R+G 与 R−B 的阈值 | 不能仅凭标签假定可分离；实际调度须依模型字节证明或使用通用路径 |
| 四级传播 | 先压缩/量化再放大，先裁剪再重映射 | 每级保留 RGB8，不把不可逆损失当作运行时算错 |
| 高频极端 | 奇偶棋盘、异或、固定种子的哈希随机表 | 表达能力边界对照，不设自然 ISP 的小误差承诺 |

5 个预留 case 使用不同参数与独立 seed，覆盖阶梯、窄峰、窄谷、跨通道和随机表。本轮只构造其源字节哈希，不拟合或读取精度结果。它们是公开的预声明验收参数，不能称为盲测，也不能仅因 seed 不同就宣称统计独立。

## 图片与自然场景对照

[stress.txt](../../assets/hack-v1/stress.txt) 是 **14 张 1024×768 RGB8 PPM** 的独立列表：4 个分布各有原布局、固定 seed 重排和按颜色聚集三种布局，另有窄峰恒色图和交替图。每组三种布局的像素多重集逐字节相同，清单保存多重集哈希；空间顺序改变不应影响逐颜色映射。PPM 直接保存 RGB 字节，避免 PNG 压缩器版本改变文件哈希。现有解码入口支持该格式。

压力图片是预声明的候选颜色与分布，**不是未经扫描就宣称的全局最坏颜色**。后续完整色域发现热点后，可通过 `hotspots` 命令把已有报告的 `cube.hotspots` 或 `hotspots` 转成 ±1 邻域及同多重集图片。被裁剪到 0/255 的重复邻域颜色会去重；输入报告的哈希随反例保存。

[manifest.json](manifest.json) 另行绑定现有 [100 张日常照片](../../assets/photos/README.md) 的来源清单与列表。图片不复制、不替换旧队列，本轮不用于调参或精度验收。图片来源、使用范围与先前参与研究的事实保持原说明，不把它们重新包装为从未用过的独立留出集。

## 两层验收与“稳定性”

完整口径见 [acceptance.json](acceptance.json)。历史 `Delta-E` 在这里明确命名为 **`rgb_l2_code_value`**，即 `sqrt(dR²+dG²+dB²)`，单位是 RGB8 码值；不是 CIEDE2000，不新增 Lab 阈值。

同一合法、量化后的四级模型，运行时相对独立整数 oracle 的容许差异为 **0 字节**。模型对完整 LUT 的近似误差另外记录 mean、RMS、p99、max、阈值超限比例和最坏/top-k 颜色；没有正式阈值时超限比例保持 `null`，不虚构精度通过率。逐图与全色域数据分开，mean 改善但尾部退化必须同时呈现。

建议未来真实场景主要看逐图 mean，同时保留 p99、最坏图和全色域 max；边界/极端场景先报告分布，按具体任务另定阈值，不要求所有任意 RGB8 变换通过一个小阈值。当前尚未把该建议当作官方判定。

输入 ±1 时，分别保存精确参考变化、稀疏输出变化及两者变化向量之差。参考在阶梯处的真实跳变单列。模型节点 ±1、源表条目 ±1、重新拟合的 seed/网格敏感性属于不同实验，必须绑定新模型/源哈希与预算，不能与固定模型的运行时确定性混淆。本轮没有执行这些扩展矩阵。

## 小型回放与最小性边界

[replay](../../assets/hack-v1/replay) 提交两组四级 m17 模型、43 个固定颜色、精确参考、独立整数 oracle 输出和平方误差：

- 恒等抵消链作为零误差控制。
- 宽 1 的内部窄峰作为采样漏峰候选。模型使用**整数取整的均匀网格**，直接采样节点；峰没有落在节点上。它与未执行的浮点均匀网格方法矩阵分别标记。

回放用于区分“同一模型算错”和“采样得到的模型误差大”。即便候选相对精确参考有 96 码值的误差，只要运行时与整数 oracle 一致，也不能判成运行时错误。该候选不构成最优拟合也无法表达的数学证明，未做全局最小性证明；其他网格或拟合方法仍可能改善。

窄峰 case 的前两张**完整源表不同**，但采样后的前两张稀疏表字节相同，这是漏采样见证，不是误把两张源表复用。独立源身份保留在 catalog/sources 中；小型回放不导入原矩阵冠军账本，也不当作带完整缓存来源证明的正式提交批次。

本轮集中核对已通过：25 项 Python 回归，7 个已编译整数后端对两组各 43 个颜色与独立 oracle 零字节差异；两张标准尺寸 PPM 也通过 C99 路径。窄峰恒色图的 mean/RMS/p99/max 均为 96；交替图的 mean 为 48、RMS 约 67.8823、p99/max 为 96。它们只是这份冻结采样模型的局部结果，没有全色域或其他方法的外推。[阶段证据](../../report/data/hack-v1/README.md)。

## 复现入口

在项目根目录、配置好的 Python 环境中运行；Pixi 可使用 `pixi run --locked python -m lutlab ...`：

```bash
# 构造版本化压力图、小模型与完整源字节哈希；没有拟合矩阵或性能循环
python -m lutlab hackset build
python -m lutlab hackset inspect

# 显式导出一个 case 的四张完整表，约 192 MiB；不导出其余 case
python -m lutlab hackset export --case interior-peak-w1 --output data/hack-v1

# 从已经存在的验收报告提取候选热点，不触发全色域扫描
python -m lutlab hackset hotspots --input path/to/validation.json

# 仅小型确定性回归，需要已构建的 jshc；完整源 LUT 不在常规 CI 中生成
python -m pytest -q tests/test_hackset_contract.py
```

`build` 对已经存在但内容不同的文件报错，不覆写冻结版本。生成器身份规范化源码换行，源算子使用整数运算；JSON/列表固定 LF，RGB 图片和模型按二进制保存，以支持跨系统复现。实际版本、构造与核对结果见 [validation.json](validation.json)。常规 CI 仅运行小型回归；`sample / ls_tetra_int × m17 / m33` 只是冻结的首轮对照计划，**尚未执行**。

本轮构造环境是 Windows、Python 3.13.12、NumPy 2.4.6，图像重排明确使用 PCG64。当前 Linux/Pixi 锁文件的依赖版本不同，本轮没有验证该环境重构时的字节一致性；不能把换行规范化等同于已完成跨平台验收。已提交的图片、模型与哈希可直接用于核对；不同库版本产生不同字节时，`build` 会报错而不会更新旧清单。
