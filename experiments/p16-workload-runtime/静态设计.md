# 92显式预计总像素门控共享首级准备

91已表明ordinary共享首级的精确direct能提高热吞吐，但每次构造完整16MiB直接表使首1/10图墙钟仅保留约15%/30%旧87速度，低于50%底线。因此91不适合作为普遍默认。本阶段独立复制91的实现，保留87默认共享cached，仅在调用方明确预计同一句柄整个生存期映射至少2^26像素时允许共享首级direct资格。固定阈值67,108,864是4倍RGB8完整域，依据91已见冷/热取舍提出一次保守机制，并非事前推导的最优值；不扫描或依新结果调整。

旧 `jshc_cc_create` 使用hint=0；新 `jshc_cc_create_for_workload` 接收uint64提示。提示只作比较，不按hint大小分配、循环或读图，也不保存在Handle，因此极大提示不会导致相应大小分配或乘法溢出。它表达生存期工作量，并非保证实际单次apply大小。调用方可以错误估计：低估仅放弃共享direct，高估会支付完整prepare代价；结果像素不变。非共享首级a399仍走87已有direct资格，不受hint门控，避免88省略快表导致的热吞吐失败。

生命周期选择参考[FFTW官方教程](https://ftp.fftw.org/doc/Complex-One_002dDimensional-DFTs.html)：其区分快速估计的plan和投入更多初始化时间的测量plan，并将重复执行次数列为选择依据。这里借鉴的是让调用方显式表达摊销机会；本实验不运行在线搜索、不更换整数算法，也不从FFTW推导本项目阈值，2^26仍须独立同场验证。

共享资格仍要求原完整域证明、首级及后三级shared、CPU/OS支持AVX2、全部cache的唯一值≤255；失败继续原共享cached路径。完整表只使用模型和后缀缓存，不读照片、目标LUT或oracle。共享数学和分配失败安全性继承91；不修改 `domain_fast_enabled`、任何pixel TU、插值式、模型或坐标。default及低hint的持久容量应与87相同；高hint共享direct额外16MiB必须分列容量、临时prepare及实际RSS。

Python包装在ctypes转换前只接受0..UINT64_MAX的Python int，明确拒绝bool、负数、超界、浮点、字符串与NumPy整数。C ABI本身unsigned，原生调用者的有符号转换意图不可检测；不把它宣称为原生负数拒绝。新的阈值getter供冻结合同检查，默认接口及1..4级/异常输出置空合同保留。

质量须独立构建92后执行：ordinary和a399默认/阈值下/恰阈值完整RGB8对87 scalar1，并比较scalar1/4、AVX2原地1/4和真分离1/4；边界值0、阈值−1、阈值、阈值+1、UINT64_MAX均作有限/u64/资格/容量检查。保留91八个固定合成模型的独立uint64 oracle，固定低hint与高hint都验资格失败回退；不拟合、不参数扫描。无AVX2硬件与分配失败若未注入须明列。

性能另冻结一次N1/10/85/86/100、1/4线程、纯apply/真分离。每图786432像素，N85=66,846,720低于阈值，N86=67,633,152超过阈值，两侧均必测。每N新句柄hint=N×每图像素，完整文件读取/解析/校验、suffix准备与可能direct编译均计入nativecreate；continuous create→首组真分离4线程墙钟与热吞吐分列。照片解码/输入hash、末组实际输出hash计时外。默认、低hint与高hint都不能靠热收益豁免冷墙钟50%门禁，控制失效保留且不补测挑样。此文件尚为静态设计，构建、正式质量与性能须等根代理分配窗口。
