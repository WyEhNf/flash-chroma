# P4 两阶段正式计时预注册 v2

本协议在正式计时前增强候选自身稳定性控制。`page-id16-performance-design-v1.md` 及其四个入口保留为未执行的静态草稿；原 41 调用/cell、656 调用总计没有执行，也没有据此授档。v2 仅复用 v1 `bench_page_id16.py` 中的身份校验、0x55 允许集、模型创建和资源快照辅助函数，不调用 v1 的 worker 协议。

数学、P4 唯一 ROM、两份已验证 DLL、原 linear ROM 和旧 linear DLL均保持质量阶段的字节。六角色固定为 ref78、ref80、linear_avx、linear_c99、p4_avx、p4_c99。模型全部同时驻留；每个 worker 的所有角色使用同一输入与输出地址。完整 100 图共 235,929,600 B，每次 native 调用前复制原输入，调用后在计时外核完整输出 SHA。模式为 1/4 线程、原地/分离输出四种。

四个 fresh worker 顺次执行。每个设置并读回进程允许集 0x55，即 logical CPU [0,2,4,6]；记录每次调用前后 CPU 号及实际 src/dst 地址。这不等于逐 OMP 线程绑定、锁频或旧未绑定漂移原因证明。worker i 的第一阶段角色顺序为六角色左移 i 位，奇数 worker 再反转；第二阶段严格反转第一阶段的完整角色顺序。偶数 worker 的线程/输出顺序为 [1,4]×[in,out]，奇数为 [4,1]×[out,in]。

每个 cell 的固定序列如下：

1. ref80 预热 1 次，外围控制 before 2 次，phase=0。
2. phase=1：按第一阶段角色顺序，每个角色预热 1 次、记录 timed 5 次。
3. phase=2：按第二阶段镜像顺序，每个角色预热 1 次、记录 timed 5 次。
4. ref80 外围控制 after 2 次，phase=0。

每 cell 共 1+2+2×6×(1+5)+2=77 次；每 worker 四 cell 为 308 次；四 worker 为 1,232 次，含全部预热、控制和 960 次角色 timed 调用。所有调用均保留整数 wall_ns、返回值、完整输出 SHA、CPU 与地址。另有六个独立 fresh RSS 进程，各仅创建一个固定角色，记录同 imports、同身份预检、准备前/准备后/关闭后快照；RSS 不计入 1,232 次像素调用。RSS 包含 Python/依赖库/模型准备成本，不称纯模型内存或 prepare 专属峰值。

稳定性门预先固定为闭区间 [0.8,1.25]。每 worker/cell 的 ref80 外围 after 两次均值 / before 两次均值必须过门。每个六角色还必须满足该角色 phase2 的五次中位数 / phase1 的五次中位数过相同门。任何一个控制或角色不通过，则该 worker/cell 的六角色全部失效；只要四 worker 中有一个 cell 失效，该线程/输出模式的六角色均不授任何档。raw 比值仍完整保存，不补跑、不删调用、不修改边界、不取十次合并中位数或平均值救线。

主速度分母是同一 worker、同一 phase、同一 cell 中 ref78/ref80 五次中位数的较快者。候选速度保留率为该分母耗时 / 候选同 phase 五次中位数；每模式取全部四 worker、两 phase 共八个比值的最劣值。100/90/80/70/60/50 六档以精确 Decimal 比较；只有该模式所有稳定性门有效才授档。只有四模式全有效才可给全模式档。有效低 50 是数值反例；失效模式是尚未证明，不把 raw 低值写成有效反例。P4 与匹配 linear kernel 的同场比值仅为辅助，不作为主档位分母。

精度单列为 100% 保留，依据已冻结质量阶段的完整域、100 逐图、独立 u64 oracle 和边界拒绝；其含义是输出与当前 a399 模型位等价，不是相对数学参考误差为零。计时控制失效不改变既有精度事实。临时 RSS、ROM/借用 ABI、静态栈分别报告；不可将 RO 减少 private commit 当作模型容量或物理 RAM 减少。

质量独立审计必须先通过。正式冻结绑定所有执行源、v1 未执行草稿、质量原件、模型五输入、原/新 ROM、实际四 DLL 所在目录中的依赖 DLL、完整照片和输出身份。执行前必须等待 root 的明确排他 grant。首次身份/native/输出失败 STOP 并保存已有原件；稳定性失效不增加采样。任何两阶段结果不改变冻结角色、编译器、允许集、顺序、轮次、阈值或格式。
