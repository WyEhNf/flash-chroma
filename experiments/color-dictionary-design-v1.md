# RGB32预展开块字典：唯一版本预案

Agent：`/root/memory`。Operator：当前任务用户。Task：16题内存与可移植性独立分支。Status：In Progress。

本阶段用容量换取一条更短的精确查表依赖链。旧3B路径为输入→LE24 map→8bit ID→palette RGB32；唯一新版本改为输入→LE24 map→RGB32，原107707个16像素块各展开成64B，保持块顺序和全部颜色。该机制不调整a399四级模型，不读取gold或照片来选择参数，不改变默认后端。

格式固定为M16C v1：32B头、3145728B LE24绝对payload偏移、6893248B连续RGB32块池。RGB32用显式小端字节序，最高字节必须为零。payload共10038976B，ROM共10039008B；新借用对象在Windows x64预期32B，实际由DLL导出`sizeof`核验后再使用，预计常驻10039040B。旧3B常驻4871152B，本分支同场78/80现有容量28046644B；两种基线分别列出，不借用速度分支后续85/87的独立容量。

LE24 map指向64B块起点。准备阶段验证整个map、偏移界限、块对齐和所有RGB32最高字节，要求整个payload不超过24bit地址空间。新C99核心标准字节读取，无堆、无浮点、无ROM对齐和用户额外padding要求。8像素批次先读取全部输入对应的颜色地址，前7项`memcpy4`，第8项`memcpy3`，短尾逐项3B，保证同址原地处理与图像末端安全。

AVX2沿用冻结3B的输入循环、预取、输出布局及线程块划分。只将`lookup_id`变为`lookup_color`并移除依赖palette读取。map末项用4B `memcpy`读取时额外一字节位于同一合法非空pool内并被掩掉；最后颜色4B读取结束于真实ROM末端，无越界padding假设。C99仅读取map的3B。保留完整RGB24合法输出值，不引入230色或256色运行时限制。

在导出/构建前记录全部实现、生成器、工具、输入哈希与唯一冻结JSON。导出独立重建全16MiB逻辑ID和RGB32序列化值。native质量覆盖纯C99、桌面scalar及AVX2单/四线程完整256³ SHA；零长、短尾、原地/分离、非对齐、非法ROM与地址拒绝、C99/AVX图像保护页、ROM保护页，并强制最后map指最后pool像素，另测试任意高值RGB24。

质量通过后仍须等待root正式排他窗口。预冻结五角色为78、80、旧3B、新AVX2 RGB32、新C99 RGB32；四新进程各按轮转/反序执行双接口单/四线程，预热1次后5次完整百图。每进程用当场较快78/80作分母，四进程最劣吞吐分别判断100/90/80/70/60/50六档。A/A任何单对越0.8..1.25或中位越1/1.1..1.1均清空相应正式档位，原始观察保留。逐字节无损只给100%精度资格，不能替代速度资格。旧3B此前有效39.8454%反例继续有效，本轮不恢复其稳健全情形50推荐。

每角色另取新进程RSS，输入SHA用流式`file_digest`，RSS包括相同Python/NumPy/运行库/导入基线，不能称纯核心RAM。源代码静态stack usage、真实ROM与借用对象、离线导出峰值分别报告。当前未执行导出、编译、质量或计时；性能执行须由root另行授权，不以预案容量冒充已测结果。
