普通af974四级链已有suffix cache和完整域证书，但87的 `domain_fast_enabled`还要求首级非共享，所以未尝试直接编译。此目录从8381974的runtime原字节独立复制，只有revision与构造资格两处改变；90冻结源、pixel TU、domain证书、逐级RGB8、模型及默认入口不动。

不全局放宽 `domain_fast_enabled`。仅构造时允许 `domain_proven && 首级shared && 后三shared`尝试原直接编译器。palette仍须≤255、CPU/OS须AVX2；超255或分配失败继续原共享cached回退。因而失败模型不会被迫运行历史非共享domain核，避开修订15共享布局曾有的静态退化。

## shared轴与插值式核对

原构造函数对无sidecar的首级，把 `axes[c][a]`三通道都设为 `packed.axis+a*256`，指针直接相同。对三份相等但与原模型不同的sidecar，先逐Q16验证与比较三份fraction，再逐份OR相同idx；指针可以不同，值相同，不能丢弃自定义共同坐标。新资格复用原 `View.shared`判断，无另外近似判断。

原直接编译器调用 `transform<false>`。该式先用通道0三轴的idx算base与n0/n3，再分别按各通道fraction执行相同geometry及整数interpolate。对shared，各通道fraction值相同，三份geometry严格同输入、同稳定比较、同节点偏移，故与 `transform<true>`复用一次geometry逐式等价。额外轴gather只增加prepare工作，不改变像素值。65536端点保留在 `0x1ffff`掩码内，没有改成65535或浮点重算。

首级R依旧为凸重心，落在节点R极值之内。共享坐标下G−R/B−R是同权重节点差的凸组合；既有证书中各通道fraction差为0，区间斜率附加项为0，仍验证完整可达cell的差值上下界落入cache。新代码继续要求证书通过，不以“共享通常接近灰色”跳过证明。

cache index公式及生成顺序完全复用87；完整prepare按256个65536块编译2^24个u8 ID。每次8个ID经memcpy写8 B，起点/长度为8倍数，表分配2^22个u32；末写在2^24字节内。prepare只读取四个模型及其后缀缓存，不读取完整目标LUT、照片或oracle。palette数值包含原缓存的无效0槽，仍保守按全部cache唯一值≤255，未改成输入相关缩小。

## 数值前冻结的验收意图

1. 先用共同87诊断ordinary缓存唯一输出数、完整域证书及fast/direct标志，再构建91；若超过255，保留负资格，不扩为16位ID或扫描其它模型。
2. ordinary af974与现a399分别做完整RGB8的87 scalar/91 scalar/AVX2 1/4线程、原地/真实分离逐字节比对，并记录库/模型SHA和构造实际容量；首级相等侧表也必须保留其共同坐标。
3. 覆盖单级、混合后缀、>255 palette以及无资格/尾部/偏移/哨兵，确认失败仍用旧共享路径。分配失败若未故障注入须明列，不以静态catch当实测。
4. 性能另冻结：同模型旧87/新91纯apply与真分离1/4线程，完整prepare及prepare+首1/10/100图分列，所有输出实际SHA；N1若首次摊销失败照实保留，不用热吞吐豁免。不得把ordinary/a399不同模型的绝对速度相除。
