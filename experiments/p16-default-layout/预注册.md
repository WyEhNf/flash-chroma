# 93默认小N路径的窄原因辨别（静态预注册）

92 ordinary N1/T1/inplace四个worker比为0.911590、0.974057、1.012771、1.214991。最后worker的3.7525ms对3.0885ms及各自AA1.01666/1.08710均有效，故92的80档必须保留，不能按其它失效项补跑恢复资格。本阶段只考察这一已有效退化场景，不调整2^26提示阈值，也不再测N10/85/86/100或精度新模型。

只读核对发现87与92六个AVX2对象文件SHA逐字节相同（cached、andn in/out、normal、exception等）；runtime的jshc_cc_apply、apply、apply_omp、apply_to_omp四函数归一化反汇编201/143/178/357条相同。apply相关RVA相同，外部hot符号仅整体平移0xc0。hint不保存进Handle，没有新增热操作，但这不能否定DLL/heap/调用分块/CPU调度状态所致的真实有效退化，亦不能据此作频率因果声称。

固定ordinary首图N1、AVX2单线程、原地纯apply、两库默认create。4个独立进程各运行全部2构造序×2对句柄×2共同work偏移×2调用顺序=16个cell，合计64 cell；不得筛选。每构造序ABBA或BAAB同时存活两对句柄，在两个work布局和两个顺序中复用不重构；构造顺序本身只是heap布局代理，不等价固定table地址。公共ABI不公开cache数据指针，记录不可取得，不能声称控制heap。句柄、模块和函数地址，以及work mod64/mod4096和源地址均记录。

同一进程始终使用同一source地址和同一backing工作区。布局0为64B对齐基址，布局64为其后64B，两者mod64都为0但mod4096相差64。两库每cell使用完全同一个work指针，两个重叠视图仅串行使用且与source不重叠；每个原生bench内轮先复制源，纯apply时钟排除该copy，copy_apply数组及外部wall完整保留。输入/输出hash、毒化和caller CPU端点在wall外；端点相同不证明内轮未迁移。

两种调用顺序都每role9个C ABI块×7内轮=63正式轮，AA同样63；warm每role相同2轮。blocked先完整A九块再B九块；interleaved交错18块，每个相邻块对镜像角色次序。这样原生边界数完全相同，只改变调用先后。两种顺序亦会改变两张cache的共存状态，若产生交互，只支持“角色分块状态混淆”，不能唯一归因CPU频率或纯时间漂移。

每块末实际caller-owned work SHA核验，原始7轮apply/copy_apply与wall/CPU端点保留；含warm合计2432组实际SHA，16128正式/AA内轮及256warm内轮共16384次整首图映射。每cell各role拼接9块的63数取中位，AA严格0.85..1.15，四worker配对后按最劣吞吐100/90/80/70/60/50。保留全部慢轮和失效，不补测或放宽；此处资格只属于新诊断，不回写92。

预注册的交互兴趣线为比较两cell的candidate/reference比：同一因素两水平之商在至少3/4 worker同向超出±10%，其中位亦超出相同线，且两个cell全部AA有效，才标记该因素有可复核交互；否则保留未解。固定句柄/work时改变blocked/interleaved辨别角色分块状态；固定句柄/顺序时改变共同work偏移辨别caller布局敏感；构造序反转仅辅助判断分配先后交互。10%是原因研究的事前兴趣线，不是用户50底线，也不是统计显著性或因果证明。若交互不存在且仍慢，保持原因未知。

进程允许CPU0/2/4/6，未逐TID单核固定；不锁频温控、不宣称目标Intel。正式前只做默认cached容量/指针/首图输出的短接口质量，不以其短计时论速度。根代理在自身训练单扫、tail288八角色及其它质量全部释放后另授正式排他窗；静态预注册时未运行此诊断。
