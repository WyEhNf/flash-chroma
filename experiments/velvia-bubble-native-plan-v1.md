# 固定κ3两cell的原生后端与配对设计（仅静态）

代理 `/root/tail`；操作者为当前会话用户。状态：待独立构建/质量/性能窗口授权，尚未编译执行。本计划只落实已冻结两cell方案，不新增节点拟合或根据照片调κ。原模型仍为Velvia原3e5f，目标完整输出SHA为`f38217d6ab471f58cc794eee23ab02317f4df2d86b0a00eab4f520e2b4ba3875`。

以speed分支revision87的实际源码和编译宏为后端，建立单独研究target，不能替换冻结的87 DLL。原3e5f和κ3候选使用同一个新DLL、同一加载器和同一标量/AVX2像素路径；另保留冻结87 DLL的原3e5f对照，避免新DLL的共同调度开销被同库比值隐藏。记录原源码SHA、实际DLL SHA、编译器和完整flags，禁止把派生新DLL标成原冻结87 SHA。

首实现只增加两cell的局部覆盖核。保留87原65536像素的外层OpenMP分块，开启功能后在每个块内按4096子块处理：写入前判定原输入shared-idx cell，保存命中像素位置及计算好的RGB8结果；其余执行原87的同一像素核，再覆盖命中结果。关闭功能仍按原65536块调用基核，开启功能的额外子块调用属于候选代价，须计入实际耗时。不复制完整输入，不建立完整RGB域残差表，不重定义原SLUT文件。第一版使用固定块内栈数组，最大4096条命中都必须安全，不能假设自然照片只命中很少颜色。若每条记录按uint16位置及RGB8存储，实际sizeof和每线程栈上限须从编译结果报告；不得只报句柄容量而遗漏栈暂态。单级Velvia不触发Cinema四级suffix/direct资格，须从本模型实测诊断确认。

覆盖核按既有共享idx和每输出Q16坐标读取原节点，分别求mask0与mask1未舍入累加器，以64位整数实现w=min(65536,3t)与Q32一次舍入。选定cell及κ必须固定在明确的新研究入口，旧create默认关闭；显式启用只接受33³、单级模型，其他形状拒绝，避免静默对其他模型应用这两个cell编号。新功能标注非stock SLUT、题面许可未知。启用后既有apply和apply_to都必须支持，不能让其中一路偷偷回原输出；不支持的入口应明确拒绝。

正确性先于计时：新DLL关闭功能的全16M输出应等于原945d流及冻结87；开启功能全16M应等于f382流。标量1线程、AVX2的1/4线程各逐字节复核；真实100图新鲜前向及分离输出/原地输出均应与完整流一致。边界长度、命中密集块、无命中块、原地/分离输入、非法参数以及尾部不足8像素需小合同覆盖。C0和邻接统计沿用固定数学输出，若原生逐字节一致则没有新的质量选型；保留原质量证据和R/G局部跳变增大的限制。

配对性能必须另获排他窗口。冻结87基线与新DLL关闭功能先做A/A控制，随后同新DLL的关闭/开启两模型随机或交错顺序测试，纯apply及包含复制的总耗时分列，原地与真分离路径分列，1/4线程分列；prepare与冷首分列。固定图片、重复数、进程数、A/A允许漂移和结束条件后执行，所有worker及失败样本保留。报告中位与最坏吞吐保留，按100/90/80/70/60/50档逐项判断，不只挑平均。任一冻结关键速度观察低于50%即不作为用户底线通过项；不在同一次试验内换核、换线程或删worker救结果。

实际运行容量同时报告两模型的句柄及分配容量、每线程额外栈上限、构造高水位和RSS；不能用12字节理论元数据代替整后端真实开销。此阶段不涉及AVX512，也不能把本机AVX2速度推断为其他平台结果。若新DLL关闭功能相对冻结87出现显著开销，必须单独披露该开销后再谈同库候选收益。
