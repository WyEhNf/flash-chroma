# 逐TID控制第二个质量夹具：保证实际四线程

第一版构建记录器在编译调用之后遇到Path/str元数据错误，原源和目录保留；仅修记录器的第二次构建成功。随后第一版质量使用65537像素请求4线程，但原运行时按ceil(pixels/65536)限制实际worker，只有2个；调用后3/4号池线程被替换，snapshot核同TID失败，原partial/冻结保留。它没有证明构造阶段换线程，首次构造后的snapshot本来相同，也没有计时。

新独立质量脚本固定786432像素（12块，实际min(12,4)=4），沿用同一已构建helper、同一87/94/a399/oracle。完整四worker的pin/构造/apply/snapshot/restore合同不改，不重建helper、不改原质量源码或原件。通过仅证明这些连续实际四线程调用能维持绑定；1/2/4的team尺寸变化仍会影响池身份，后续控制必须逐场景重新核验，不能泛称任意生命周期一次绑定即可。

本协议在v2质量执行前固定，无速度/A/A结果，不能恢复任何旧失败。仍只作用于独立新测试进程，不对其他程序、系统CPU策略或已冻结95/C7BK做修改。
