# R16：五项发展方向的实现与实测报告

日期：2026-10-13。分支：`codex/zig-default-pixi`。本报告的结论仅针对本项目生成的 `isp-0` 场景、29 张精度图、100 张吞吐量图和 Arch Linux WSL 上的 i7-13700H。正式比赛的 `Threshold`、输入 LUT 格式、判定粒度及单阶段复合的合规口径尚未公布，不能把本地通过等同于官方通过。

## 1. 精度门禁

新增 `python/lutlab/validation.py` 和 `pixi run validate`。用真正的 `jshc cube` 可执行路径生成全部 `2^24 = 16,777,216` 个 RGB 输入的输出，与四个完整 LUT 精确顺序查表得到的 `composite.lut256` 比较。门禁逐张读取 29 张评测图，使用未四舍五入的每图统计量，以严格 `< Threshold` 判定；可选择 `mean`、`p99` 或 `max`。日志保存每图 mean/RMS/p99/max、失败图像、全色立方体 mean/RMS/p99/max、最差颜色及模型和真值文件的 SHA-256。`--skip-cube` 仅省去全色统计，仍通过立方体生成实际内核输出供图像评测。

题目只给出逐像素 RGB 欧氏距离公式，没有规定 Threshold 究竟施于整图均值、p99 还是最大值。因此本次扫描**明确使用本地示例条件：每张图平均 ΔE 严格小于 2.0**。它不是比赛阈值。单独验证命令：

```bash
pixi run validate --scenario isp-0 --metric mean --threshold 2.0 --threads 20 \
  data/models/isp-0/residual_ls_tetra_int_m17/stage{1,2,3,4}.slut
```

初次基线验证日志 `059a57e9`：m=33 四阶段 Zig 版本 29/29 通过，最差单图均值 1.6012；全色平均 1.3235、p99 3.6056、最大 9.6954。最大误差颜色为 `(127,254,97)`。这里的“通过”只针对上述本地均值条件。

## 3. 尾部误差与网格算法

新增两类拟合：

1. `tail_tetra_int`：先做与运行内核一致的四面体最小二乘，再根据采样点误差给大误差区域更高、上限 16 的权重，重新解法方程并做整数节点精化。
2. `adaptive_error_grid`：用均匀网格的先验模型测量误差在 R/G/B 三轴的分布，按误差密度移动节点，保持两端覆盖和至少 2 个输入值的格间距。不同网格有独立缓存目录。
3. `residual_tail`：先拟合前三层，基于**真实最终四级输出**与前三层实际输出，给末级残差目标的大误差样本加权。这比逐级独立重加权更贴近最终验收。

实测显示算法改进有条件：m=17 的逐级 `tail` 使最差单图均值从 1.702 升到 2.035，反而越过本地门槛；m=17 `residual` 把全色最大误差从 15.26 降到 10.25，`residual_tail` 再降到 10.10，但最差单图均值从 1.547 升到 1.600。m=33 `errorgrid` 的全色最大误差为 7.35，低于均匀 `tetra` 的 9.70。故应由配置化门禁选择，不应把任一种新算法无条件设为默认。

## 4. 可复现开发与交付

`data.py` 默认要求 24 张 Kodak 原图齐全；下载失败直接报错，只有显式 `--allow-synthetic-only` 才降级。`data/manifest.json` 记录生成种子、来源模式和 155 个输入/列表文件的 SHA-256；图像列表使用项目根目录相对路径。`verify-data` 检查所有文件哈希、29/100 张图的尺寸与模式，并验证 4 个完整 LUT 的原有哈希和复合 LUT 尺寸/哈希。旧数据可执行 `pixi run adopt-data` 建立清单；此操作只能固定现状，不能证明旧文件的来源。

`pixi run competition-check --threshold ...` 可在缺数据时准备图像与场景，随后构建、跑 C++/Python 测试、核验数据、执行全色精度门禁与 100 图候选筛选。阈值必须显式输入；`--metric mean|p99|max` 与 `--allow-composite` 防止规则假设被暗中固定。完整输出进独立 `logs/` Git 仓库：`run.json` 记录代码 SHA、脏工作区状态、CPU、Pixi 锁文件 SHA；`test.log` 保存测试子进程输出；`selection.json` 保存全部候选的统计、模型哈希与时间。`logs/`、`data/` 均不随代码仓库自动共享，团队需要单独备份。当前独立日志仓库 HEAD：`f21c654`（写报告时）。

本次一键流程在已有本地数据上成功完成，耗时约 124 秒，C++ 全色内核测试 1/1 通过，Python 5/5 通过，29 张图、100 张图、场景哈希核验通过。干净机器的首次下载和容器构建尚未实测；WSL 本机无 Docker 命令。Rust 的 Pixi 依赖及 `RUSTC_BOOTSTRAP=1` 构建路径仍只在本实验分支，未进入主分支。

## 5. Zig 可移植性能扫描

Zig 内核通过泛型 `@Vector(N, i32)` 提供 4/8/16 lane 三个 ABI 符号，不使用架构 intrinsic 或内联汇编。C++ 执行器增加 `JSHC_BLOCK_PIXELS=1024|4096|8192`、`OMP_SCHEDULE=static|dynamic,1|guided,1` 配置；默认块 4096、动态调度粒度 1。`pixi run zig-perf` 对 100 张图记录配置与整组时间。36 组扫描（4/20 线程 × 3 lane × 3 块 × 2 调度，3 次重复）的日志 ID 是 `37f9fba6`；其中 4 线程下各 lane 的最佳整组时间分别为 339.947、265.080、236.600 ms。20 线程下分别为 125.877、129.343、123.056 ms，负载波动显著。

固定 4096 块、动态调度后又做 7 次整组重复（日志 `20bb8ce1`）：

| 线程 | 8 lane 中位 ms | 16 lane 中位 ms | 16 lane 相对改善 |
|---:|---:|---:|---:|
| 4 | 257.972 | 243.348 | 5.7% |
| 20 | 141.227 | 135.011 | 4.4% |

据此把默认 `tetra_zig_simd` 切到 16 lane，并保留显式 `tetra_zig_simd8` 供不同 CPU 复测。C++ 测试已对 m=17/25/33 的全部 `2^24` RGB 输入核对 4/8/16 lane 与标量的位精确一致性，并覆盖不满向量宽度的尾部。当前最终一键扫描是在 16 lane 默认版本上执行的。不同 CPU 的最优 lane、线程数与调度可能不同，应在目标服务器上重新选定。

## 使用命令与后续动作

```bash
pixi install -a
pixi run competition-check --scenario isp-0 --threshold 2.0 --metric mean --threads 20

```

`2.0` 仅为复现实验用的示例值。官方数据公布后，应首先替换为官方 LUT/图像与 Threshold，并按公布的判定粒度重跑；确认单阶段复合是否允许；在官方机器上对精度合格候选重测整组中位时间。当前仅对 `isp-0` 执行本轮 24 候选完整门禁，其他 `film/warp/clip/stress` 场景仍需扩展，不能据此声称跨场景稳健。
