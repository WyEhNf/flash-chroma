# Velvia误差质量归因：照片均值与cube尾部由哪些颜色承载

照片均值主要由大量低到中等码值、小幅RGB误差承载；cube高尾部更偏向饱和边缘，二者不能用几个最坏色代表。将G两个内knots局部移到251/252，在固定RGB8节点和端点平面的限定下，即使所有可变支撑误差消失，60训练图mean最多改善2.909466%，达不到3%。这个结论只排除上述局部几何提案作为该训练测度上的3%方案，不排除全局节点重新拟合，也不能外推为20选择图/100图的数学不可能性。

距离不超过2的非零误差贡献照片mean的78.785325%，不超过3则贡献92.642189%。即使把所有>7的照片误差清零，也只有0.870875%的mean相对改善上限。这说明只修高max热点不足以带来整体mean的大幅下降。小误差占多数并不能单独证明它们全部是量化错误：RGB8舍入、共享节点拟合折中和粗网格误差都可能落在相同距离区间。

## cube尾部与照片均值承载区不同

cube的>=7尾部出现在3234个单元。最大一个单元占尾部0.528034%，前10个仅3.687399%；承载50%/90%尾部需468/1560个单元。

- G=252–255、245–251、236–244分别承载cube尾部14.117841%、7.096048%、6.428933%，合计27.642823%；但这三个区间仅承载照片误差和3.120073%、照片自身p99尾部2.131351%。
- cube尾部最大的R区间是0–14、23–31、15–22，分别10.669708%、7.114906%、6.701201%；它并非全部在高R/G端。
- B=236–244、250–255、245–249分别承载cube尾部8.978938%、6.159023%、5.747675%。
- 最大尾部单元(0,0,11)位于R/G约0–14、B约89.24–96.63，含896个cube尾色，却只对应60图68个像素。相邻(0,0,12)同样含890个cube尾色而仅67个照片像素。

因此照片mean和cube尾部是两个不同的加权目标；改善其中一个的局部尾色不能自动代表另一项改善。G最上沿值得解释其极端误差，却不是照片总体误差的主承载区。

## G顶两内knots局部移动的上界

原G末四knots为235.362442、244.615631、251.380280、255。按照要求先取整个保守支撑G=236…255，假设这里全部误差消失、其他输出不变：

- 包含2036300个照片像素，占4.315482%。
- mean最多减少0.028089224，即原60图mean的3.120073%；剩余mean至少0.872185333。
- 宽界略高于3%，不能谎称按此宽界已经严格排除；要达到3%需要消除该支撑原误差的96.151594%，几乎是完美修复。

若提案确实只移动两个G内knots，其他RGB8节点与端点平面固定，那么G=255始终使用原最后节点平面，其输出不随内部坐标移动而变化。可进一步扣除该固定平面：G255贡献mean=0.001896043、误差份额0.210607%，436688个像素。

于是实际可变支撑G=236…254即使误差全消失，mean最多减少0.026193181，相对改善2.909466%，低于3%。在“固定节点、仅局部轴位置”的条件下，可排除它作为60训练图mean降低3%的独立方案。该收紧来自已冻结CSV的减法，没有重读原流、构造新网格或映射候选；精确来源SHA与公式另存support-bound.json。

不能将此结论用于允许重拟合G255平面或全局节点的方案。全局重拟合可能改变原支撑外的输出，此时局部支撑假设已不成立。60图上界也不能替代20选择图/100图的实际门禁，不能写成官方或全部照片不可改善。

## 结论与复现

本轮支持优先解释广泛暗/中间色上的共享节点与RGB8舍入折中，同时把饱和边缘的大尾部单独处理。结合前一插值诊断，现节点在极端单元能偏离源值约46码值，且直接换三线性不改善一般探针，现有证据不能把主要问题归结为“仅两个G上沿结点太粗”。本轮没有证实任何新算法收益，也没有把小误差一概判定为实现bug或纯量化损失。
