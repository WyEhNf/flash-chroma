# 相邻节点成对整数提议：实现与集中合同

Agent：Codex；Operator：WyEhNf；状态：完成纯合成实现合同。未在Velvia或任何真实LUT上拟合，未改模型、默认方法、fit/CLI或研究驱动，未运行全域精度、百图或性能测试，未提交、推送或创建PR。

目标是解除两个共享节点在RGB8舍入下的抵消障碍：单节点±1都可能恶化且触发硬cap，但联合±1有时改善且可行。新增`python/lutlab/paired_grid.py`，并用独立整数oracle验证组合损失、真正的组合违规次数和批量缓存更新。合同通过仅证明这些实现行为，不证明真实数据上能降低mean或p99。

## 实现与边界

入口为`propose(model, points, targets, mass, *, caps, sweeps=1, parts=4, tail_at=6., tail_weight=.02, progress=None)`，返回`(checkpoints, report)`。本阶段严格只接受`sweeps=1`，固定两种tiling偏移000/111，每种8个块颜色和3个输出通道依次处理。每组先重新计算当前成对收益，再每块选最多一对；不做权重、偏移或额外扫数搜索。

节点标签由调用者提供为本级原表RGB8输出，模块不使用其他阶段、后缀或复合/残差标签。固定RGB8节点的同一输出通道，只检查两个端点各±1的四种组合。固定grid/idx/frac，不增加模型字段或改变运行时。

每个节点单独计算完整正支撑上的损失变化；对两个节点共同支撑的行，再加`rho(joint)-rho(a)-rho(b)+rho(old)`。损失是RGB距离加6码值以上0.02倍二次尾罚，使用float64质量归约，不称无理数严格数学证书。

硬cap按每一行的真实误差平方实施，包括零质量行。单端违规次数先相加，再对共同支撑加`violation_joint-violation_a-violation_b`，使用有符号int64计数；归约后负数触发断言。不能把两个单端禁止位OR起来。起点本身超cap立即拒绝；RGB8节点越界方向全局禁止，不依赖该节点是否有训练支撑。

边以`lower_node*7+kind`编码，正差为坐标各分量0/1的7种非零可比差，只保留同一2×2×2节点块内端点。同色块之间相隔4个节点，任一四面体正支撑最多触及一个同色块。批量更新先累加当前像素所有四个顶点的移动贡献，再更新一次输出误差，避免旧单节点代码中遇第一个顶点就break的错误。

每扫结束重新从I/W和完整节点数组计算全部acc、d²、损失和逐点cap，核对增量缓存与预测收益；只在实际目标明显下降时返回新检查点，否则返回原模型。该一轮分块不覆盖所有对角边，不是全局最优证书；进一步使用仍需独立选型和完整终验。

I/W、初始acc和d²复用`rounded_grid.prepare`。没有边×全部支撑的常驻缓存。m33、parts4单次收益函数的主要私有/输出数组估算约85.10MB；当前循环下一次调用期间仍可能与上一组返回的约16.10MB输出短暂共存，另有小型布局/选择数组。此项仅为数组尺寸分析，没有实测峰值或速度结论；完整训练的I/W、输入、标签、质量和cap需另外计入内存。

## 集中结果

固定4像素反例：m17轴为0,16,…,240,255；节点全部为10；a=(0,0,0)，b=(1,0,0)；输入R=0/6/10/16、G=B=0；目标R=11/10/10/9、其余10；质量0.1/0.4/0.4/0.1；cap=1/0/0/1。

| 改动 | 实际目标变化 | 单改/组合违规数 |
|---|---:|---:|
| a的R+1 | +0.3 | 1 |
| b的R−1 | +0.3 | 1 |
| 两者联合 | −0.2 | 0 |

共享行的违规修正总数为−2，将两个单端违规正确抵消。选择器选中该一对，整扫目标0.2→0，输出精确等于四行目标，预测收益差0，原grid/idx/frac保持不变。额外确认两扫请求与起点cap违规都被拒绝。

随机合同固定seed=2026101911，519个RGB8点，随机RGB8节点/标签，真实Q16权重含一个非canonical分数、31个零质量行和逐行不同cap。

- 125种合法成对变化与独立oracle比较，最大目标变化误差8.3114e-14；组合违规总数全部相同。
- parts=1与parts=4的收益最大差3.4694e-18，违规计数逐项相同。
- 21个全局节点边界方向被禁止，包含不依赖训练支撑的检查。
- 两种tiling各选44对做同色多块批量更新，分别有21/20个像素同时受至少两个移动顶点影响。实际RGB8输出、增量acc和d²分别与独立oracle/整缓存重算均为0差；批量目标预测差最大4.6796e-14。
- m17/m33的两个tiling逐一枚举所有网格单元的6种四面体；每个tiling分别检查24576/196608个四面体，同色不同块不同时落入一个支撑，所有有效边无越界且为块内0/1正差。每个tiling有效边数分别10712/81712。

## 接入说明与已知限制

根代理可显式接入此API。`caps`接受逐行整数数组或统一整数上限；mass要求有限、非负、总和1。`progress`每组给出offset、colour、channel、selected_pairs和predicted_objective_change，共48组；返回的检查点编号只有1（通过真实目标改善）或0（原模型回退）。

调用者须另行绑定本级原表标签、训练测度、模型与逐点cap来源。本模块本身不能证明传入标签就是题目指定原表，也没有复用后缀或端到端约束的接口。它只解决有限配对提议的计算正确性，不能把本合同或单个支持集上的改进外推成完整精度收益。
