## 实际结果：容量下降，速度按两个参照分开解释

18个串行调用均成功，实际内核tetra_avx2、4模型、100图、m与模型/程序SHA匹配；每调用5个完整集合值都保留。下表是三进程中位值，单位ms/图：

|原DP17³|1|8.63624|8.75633|75196|179020|
|原DP33³|1|9.33921|9.45791|448252|1048460|
|解析17³|1|8.87930|9.00192|75196|179020|

相对原33³，新17³观测映射时间1/4线程分别降低约4.92%/8.09%，文件容量降低83.22%，程序模型记账降低82.93%，同时精度已由相邻独立阶段证实归零。相对同容量原17³，1线程观测反而慢约2.81%，4线程约快0.59%；小差异和重叠区间不足以证明所有配置加速，不能省略单线程取舍。

RGB8节点负载58956对431244字节；工作帧2359296、100图预载235929600字节均相同；AVX2每worker块scratch为0。观测OS峰值约245–246MB，主要由图片预载构成，不等于模型独占内存。硬件、后端和全部计时范围相同，但容量比较同时改变m与插值政策，不能把全部速度差归因为坐标校准本身。
