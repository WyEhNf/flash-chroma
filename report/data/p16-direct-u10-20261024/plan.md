# 289固定10bit精确直接索引（当前仅设计，未构建或计时）

288保持32MiB的uint16索引，当前两候选whole-cache palette603/703色。新独立版本保留旧8bit优先，仅在完整cache有256..1024色且原四级域证明成立时使用10bit，其余精确回退原cached路径。不会用“实际可达色≤255”替代完整cache证书，也不修改旧87/287/288原件。

四个10bit ID打包5字节，完整16,777,216输入数据20,971,520B，另4B guard。输入地址仍R低/G中/B高。第a个ID起始字节为5*(a>>2)+(a&3)，位移2*(a&3)；按字节组成小端uint16，再右移并mask1023，最后一项恰读到数据最后字节。保留4B guard使诊断/潜在32bit读取也有合法边界，不让调用者提供padding。

准备阶段从8个uint32 ID直接形成两组5B，不先分配32MiB uint16表；每个ID高于1023必须拒绝，不能截断。全域编译仍使用288首级通用精确几何；本阶段不混入速度分支94的shared prepare优化。旧8bit路径、整个suffix cache、palette排序、其他AVX2调度、NT/普通写和prefetch策略不变，只换宽ID读取与存储。新诊断format=10/id_bytes=0（分数个字节由format表达），ABI独立命名，容量按vector.capacity实际记。

假设是减少宽表工作集可能抵消索引拆包算术；不预称L3命中、1.6倍加速或已守50。相对288预计表少12,582,912B，两个候选预计常驻约22.913MB，须核实际ABI/容量和fresh RSS。当前尚无生成、构建、完整质量或性能结果。

质量先检查palette 255/256/1024/1025范围、实际ID1023、编译拒绝1024、跨四ID组/包/页及最后RGB输入guard，ID表完整16M重新编码/独立逐项解码与288字节身份对应；三固定模型24全域、600图及短缓冲/真正分离拒绝另验。1024以上cache允许精确fallback，不借旧16bit性能。失败、OOM未注入和平台范围如实保留。

正式性能另冻结排他单版，同场必须含87a399/87旧best、288旧best、288两候选与289两候选，不能只对较慢的宽核除。完整准备、首批、稳态1/4原地/分离及实际输入输出SHA均记录；A/A失效不授档，最劣速度100/90/80/70/60/50%。先质量通过再决定正式规模，不扫描位宽或调用参数择优。
