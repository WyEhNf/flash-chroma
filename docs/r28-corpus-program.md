# R28 数据集、逐 case 最优记录与后续对照计划

日期：2026-10-16。R28构建与审计串行完成，不使用subagent。官方数据和Threshold仍未取得。

本阶段数据与账本工作已完成并通过审计，后续策略矩阵与端侧工程仍需继续。实际构建加完整检查耗时3087.655秒；内容去重后完整对象47,714,402,304字节，200条链与320张图像全部核验。另有23组探针。199个不同最终变换中，重复组是两条轴置换回归控制；12条链的最终输出为常量，均已标记。留出源没有完全重复的训练最终变换。旧验收账本包含9个源、70份不同观测；新增200个case在矩阵测量前仍为unmeasured。

## 保持的完整目标

1. 建立足够广的、带分类/强度/种子/边界标签的数据集，支持后续追加与去重。
2. 对多种联合稀疏化和插值策略作同数据对照，给出条件与容量范围内的sweet zone；每个case持续保存已测最优及失败记录。
3. 完成可审查的端侧工程改进与移植证据。不会把“存在关闭AVX2的选项”等同于已经完成移动端部署。

## 第一批数据定义

`datasets/problem16-v1/catalog.json`固定200个四表case。20个参数家族分别覆盖3档强度×3个独立生成种子：CCM、gamma、logistic、filmic、饱和度、局部色相、分离色调、三维耦合波动、可分离波动、多重线性通道乘积、硬裁剪、逐轴量化、前置量化、后置量化、耦合分块常量、斜平面阈值、球面阈值、面脉冲、边脉冲、窄色域。

另有20个结构控制：整数反转后恒等、常量输出、轴置换、角点脉冲、量化节点预算临界值、不可压缩哈希随机、整数/半位舍入。对量化级别16/17/18/24/32/33/34/64，零阶保持实际需要的轴节点为级别数+1（包含255端点），明确覆盖m17与m33的可表示边界。

每个case的四张原始LUT必须在字节上各异。内容相同的完整表以SHA256去重，case目录用硬链接指向只读用途的对象；完整真值按四次整数直接查表构造。生成器只分配小红轴块，不拼接整个case的数据批次。每个对象有50,331,648个RGB8字节。

图像为20类×4档强度×4个种子，共320张1024×768 RGB8 PPM。覆盖全域/相关噪声、中性灰、近灰、暗部、高光、主色、色相、肤色/天空/植被近似、纯色、棋盘/条纹、稀疏脉冲、面/边扫描、极值邻域、量化阈值邻域及网格平面。必须按实际RGB字节去重，另标出唯一颜色数、通道范围、中性/边界/暗部/高光像素数。它们是合成分布，不能称为真实照片。

独立探针包括完整390,152个外边界颜色、距边界1/2的完整六平面、8角点、256中性灰、固定随机颜色和m17至m33的全部整数网格节点。全LUT拟合本身见过所有RGB输入，因此“留出”指变换源配置，不是虚构未见过的输入颜色。

格式边界单列30个夹具，包括无效头、版本/保留字段/字节序、m越界、索引/Q16越界、NaN/Inf/重复网格、截断和尾随字节、完整LUT长度差1、空文件、RGBA/灰度/调色板、RGB16、错误/零尺寸及损坏图片。夹具构造不是原生拒绝测试通过；调色板容器与解码后RGB的政策差异，以及Python/原生网格元数据的一致性，需要工程阶段实际核对。

开发、校准、留出各有60个case；同种子的所有强度留在同一划分，20个结构控制单列。完整变换链字节不能跨划分重复；共享基础量化算子会被保留并披露。真值完全相同的case另报告重复组，不把它们当作独立分布证据。

强度描述算子参数，不保证近似误差单调增加；例如量化级别越少，视觉退化越强，却更可能被有限节点精确表示。完成物化后还会精确标记最终颜色集合、常量链及与训练集重复的留出最终真值，防止名义上复杂的四级链掩盖实际退化或重复。

## 每个case维护当前已测最优

`lutlab.casebook`保存不可变观测和派生索引。case绑定四张源表的顺序哈希；每条观测绑定模型字节、来源manifest、执行内核和底层测量JSON。来自采样颜色的记录不能赢全色域策略；底层JSON或模型被改动则拒绝。历史R20-R27的完整真实验收可导入，不重复像素测试。

分别维护全色域mean最优、max最优、mean/max/节点字节Pareto集合，以及按图集哈希区分的实际100图示例均值达标最优。没有测量的case标记unmeasured；没有严格配对计时就不建立“最快”结论，单次fit_s不参与速度排名。精度失败也保留，不能只收录通过case。

## 分阶段策略矩阵与sweet zone

首轮预声明200个case×3个尺寸(m17/25/33)×9个既有独立策略，共5400个候选：直接采样四面体、可分离三线性LS、普通四面体LS、DP+jitter、DP+边界、DP+完整节点支撑、DP+全色域、DP+箱约束全色域、R27证明选择。固定尺寸比较与跨尺寸Pareto分别统计。

先以实际原生完整RGB立方体映射比较候选，并对边界/近边界/网格探针单列误差；后续对每类代表性的非支配候选做实际100图CPU/CUDA或其支持后端验收，才能标为可提交配置。并非每一种插值都已具备CUDA执行实现。

开发/校准结果用于形成类别规则，规则冻结后再评价留出case。各case事后“已测最佳”与面向未知case的类别规则是两个不同对象。报告策略胜出数、失败数、m范围、精度/内存代价及未完成的对照数量，不以一个总平均覆盖不连续或高强度失败。

首个开发case的9×3完整对照已经入账，快照见`report/data/r29/`。后续可由`scripts/r29_parallel_phases.py`将开发、校准、回归三个独立划分交给三个普通进程，每个拟合器使用4个原生线程、BLAS单线程。各进程有隔离账本，唯一父进程序列化导入总账本，避免覆盖其他进程的最优记录。它不创建subagent。拟合耗时和并行精度扫描耗时不用于速度排名；性能比较只在这些重计算全部停止后单独执行。工作块上限不改变5400候选分母，留出仍须先冻结类别规则。

首个并行工作块已完成432/5400条观测。后续执行必须显式传`--source-root artifacts/r29-frozen-source/19c69a6a7554b9920301`，使用按原始字节和公共缓存身份核验过的R29源码镜像；主线已加入R33，不能将主线源码作为同一基线epoch继续运行。源压缩包有独立不可变副本，避免后续归档覆盖基线来源。

进度快照与类别规则冻结工具同样支持`--source-root`，并独占同一写入租约。运行中的拟合控制器存在时，它们直接拒绝执行，避免陈旧快照覆盖新账本，或训练报告还在改变时就声称已冻结留出规则。修改辅助工具不改变已经执行过的数值源码镜像。

第二个工作块实际遇到Windows报告替换共享冲突，R37从完整证据恢复一条未入阶段索引的观测，无需重跑像素。下一轮调度改用`r38_parallel_phases.py`：为冻结数值驱动明确加载有界重试I/O层，保留旧拟合和模型身份；必须先等旧控制器及写入租约释放。新调度器尚待首次实际执行，细节见`docs/r37-report-recovery.md`。

## 工程落地阶段的验收范围

计划新增调用者持有模型/图像缓冲的稳定C接口，支持行步长、小块/原地处理、明确边界与错误码；像素循环不分配堆内存，不依赖文件I/O、Python、OpenMP或CUDA。先证明与既有Q16四级算子一致，再针对已证明的阶梯/节点命中削减读取与乘加。

这项基础库已在R30/R31实现并完成本机与AArch64大小端模拟执行验收，见`docs/r30-portable-runtime.md`；实体手机、NEON性能、功耗及新C库的配对计时仍未测。

移植证据区分Windows实际执行、无加速构建、ARM/AArch64交叉编译、模拟器执行及真实移动设备运行。没有对应执行证据的格子保持未测，不以交叉编译成功代替设备性能或功耗。后续性能采用少量预声明7对比较，避免每个修改都跑benchmark。

## 扩充约定

已冻结的catalog不覆盖修改。新增版本保留旧case ID和来源哈希，只追加新定义或明确记录修订关系；默认采用内容寻址对象复用已有完整表。将来增加真实照片、官方格式、更高LUT位深、混合轴量化、孤立内部脉冲、JPEG/PNG输入等独立类别，并在覆盖表中保留尚未覆盖项。新数据和新策略必须自动出现为待测行，不能沿用近似case的最优结论。
