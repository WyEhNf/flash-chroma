# R26：箱约束求解与精确整数目标选择

日期：2026-10-15。串行执行，未提交或推送。继续使用本地RGB8数据；官方测试集、Threshold及判定口径尚未取得。

## 要解决的问题

R25诊断发现，clip-7/m33第一级无约束浮点解有7,021个节点分量低于0、3,158个高于255；裁剪后仍不满足箱约束二次目标的KKT条件。原流程会裁剪和量化节点，再做四轮整数精化，最终节点始终合法，但“先解再裁剪”不是完整的箱约束优化。

新增显式`ls_tetra_full_box` / `dp_full_box`研究候选，保留全部256³颜色的精确原生H、b、原DP网格、四张独立源LUT和运行时格式。对一般三维阶段求解：

`min ½Σ_c x_cᵀHx_c − Σ_c b_cᵀx_c`，约束`0≤x≤255`。

H满足R25的`H ⪰ I/64`，因此连续问题严格凸。这里不加正则项；R25原有正则化CG和四轮整数精化只用来构造可行初值及保留的整数基线。可证明为一维映射的阶段继续使用原有整数曲线DP，不经过新求解器。

## 数值求解与检查

使用以初值为中心、对角缩放的L-BFGS-B。令`S=√diag(H)`，`z=S(x−x₀)`；优化中心化二次式，避免在较大绝对目标值之间相减。该函数只需稀疏H乘以三个通道，不创建稠密H或完整采样矩阵。

库的成功标志不能独立证明完成。返回前重新检查有限性、0–255可行性、目标变化以及缩放后的投影梯度；只有KKT残差通过才返回，否则抛出带诊断的错误，不能发布部分模型。仅允许浮点舍入距离内的边界吸附，不用大幅裁剪修复不可行解。优化器在此方法首次使用时才导入，其他拟合方法不额外加载它。

本轮38个一般三维阶段全部通过，最多20次迭代；最大缩放KKT残差`1.03835e−7`，低于检查阈值`1e−5`。基于`H ⪰ I/64`及投影梯度计算的连续目标数值间隙上界最大为`5.87488e−9`。这是浮点KKT评估下的**连续、单阶段、未舍入二次目标**边界，不能当作整数模型或最终四级色差证书。

## 量化后的替换必须通过精确比较

连续解仍需量化和整数精化。新结果不一定优于旧整数结果，因而先重建R25整数基线，再比较两个整数模型的完整未舍入平方误差。H、b来自整数Q16矩：

`H=Hq/2³⁸`，`b=bq/2²²`。令`d=x_new−x_old`，则完整256³颜色的平方误差变化为：

`[dᵀHq(x_new+x_old) − 2¹⁷dᵀbq] / 2³²`。

先检查矩系数能精确恢复为整数、节点为RGB8及行乘积范围，再用int64计算安全的行乘积，最后用Python任意精度整数归约。分子可能超过uint64，不能直接用64位总和；也不能用两个较大浮点SSE相减判断符号。只有分子严格小于0才选新模型，否则原样保留R25整数节点。分子以十进制字符串写入manifest，保留完整精度。

38个三维阶段中28个严格改善此目标，10个保留原基线。所有重建基线节点的SHA都与冻结R25对应阶段一致；每组轴表也保持相同，14个一维阶段逐字节保持原样。未舍入平方误差的非退化不意味着实际逐级舍入后的RGB mean/p99/max非退化。

## 一次阶段检查和补充精度审计

15项检查通过，16.53秒。新增QP检查独立枚举四变量的全部下界/自由/上界组合，分别解自由线性系统，与新求解器比较；还检查真实不收敛会报错、输入不被修改，以及精确整数目标与独立有理数计算一致。

原生组装器和像素程序没有变化。核对R25原生源码、头文件、Python包装、全色域检查源文件、库SHA及独立COO参考函数后，复用其已通过的昂贵全色域组装对照，没有重复运行该检查。预检最初遇到Windows CRLF与LF函数文本差异；确认AST及规范化文本完全一致后修正了比较方式，原始诊断保留在归档中，没有修改数值组装代码。

另作一次不涉及LUT拟合或图片执行的整数精度审计：独立整数二次式对照覆盖奇数低位、超过uint64的总和，以及精确变化为−1/+1的两个抵消例子。后两者用浮点目标直接相减均得到0，整数实现正确保留数值与符号。

## 不替换主线，不追加性能扫描

该方法建立了完整的箱约束求解和精确整数选择，但最终精度收益不足。因此仅保留显式研究候选，不加入默认候选，不替换已验收R25方案。本轮不追加配对性能或参数扫描；单次拟合耗时只作为运行诊断保留，不据此构造速度结论。R25的映射时间对应其冻结模型，也不冒充R26新模型的吞吐率。

下一步优先考虑不连续映射的表示及实际整数执行目标，不继续扩大这个二次求解器的迭代预算。运行时及序列化模型没有增加依赖或表；箱约束模块只在离线拟合使用，控制参数和源码纳入内容绑定缓存。
