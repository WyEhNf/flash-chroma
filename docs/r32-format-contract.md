# R32：原生输入与模型格式阶段验收

本轮修复原生 CPU 对网格元数据检查不完整，以及 CPU/CUDA 将索引 PNG 解码成 RGB 后误认为原始 RGB8 的问题。它不改变拟合算法和有效模型的像素算术，也不报告性能提升。原始题面、官方数据和 Threshold 的可用状态均未改变。

## 已修复的行为

CPU 在准备和保存稀疏表时，检查网格有限、严格递增且覆盖 0–255。保存前先验证，非法输入不会留下输出文件。CUDA 原先已有网格检查，本轮为两个原生图像入口共享 PNG 原始位深/颜色类型门禁；竞赛图像必须原本就是 8 位三通道 RGB。CPU 的普通非竞赛入口继续允许其原有解码行为。

旧二进制实测接受 NaN、Inf、重复网格的 CPU 模型，CUDA 拒绝；旧 CPU/CUDA 都接受索引 PNG。上述行为及修复后的拒绝结果均保留在 `artifacts/r32-formats/stage.json`，没有覆盖旧执行文件。

## 一次集中门禁的结果

| 检查对象 | 实际结果 | 范围 |
| --- | --- | --- |
| CPU 原生入口 | 拒绝全部 30 个负样本 | 完整表、稀疏表、竞赛输入 |
| CUDA 原生入口 | 拒绝全部 27 个适用负样本 | 不提供完整表参考映射命令，其余适用 |
| C99 借用内存加载器 | 拒绝 17 个适用负样本，工作区不变 | 稀疏表，包括网格与 m 边界 |
| Python 稀疏表入口 | 拒绝 17 个适用负样本 | 保留其原有严格检查 |
| C++ 完整内核门禁 | 通过，12.50 秒 | 原有全色域对照及新增准备/保存元数据合同 |
| 有效压力模型 | CPU/CUDA 完整 256³ 输出与冻结结果一致 | 模型与原生执行文件均有 SHA256 |
| 有效图像路径 | 每个后端实际执行 100 张合成图和 5 张自然照片 | 输出逐字节等于已验证映射，后端之间也相同 |

`datasets/problem16-v1/invalid-formats.json` 仍记录负样本最初生成时的状态；执行状态以本轮报告为准。不能把负样本清单的“已构造”当作实际通过。

## 可复核的执行边界

驱动为 `scripts/r32_format_stage.py`。CPU 使用 `build-r32-format-cpu/`，CUDA 使用 `build-r32-format-gpu/`；原先的 R18/R23 扫描二进制哈希保持不变。C99 使用已通过 R30 的库，编译及对象级依赖证据见 R30。

两次驱动错误均被保留：第一次在调用 CUDA 包装器时误传 CPU 线程参数，第二次试图读取原始进程结果中不存在的 `command` 字段。第二次出错前 C++ 完整门禁已成功。本次以 `completed-cpp-gate.json` 绑定测试文件、源码、二进制和日志哈希复用这一已完成门禁，没有再执行相同的 C++ 全色域测试。其余集中检查在最终成功阶段执行。

本轮没有配对计时。负样本通过、图像解码通过和正确映射证据均不能推出官方精度达标。压力模型沿用 R27，仍有全色域最大误差 38.4187454；修复文件格式不消除算法误差。

原始误差按照题面公式为 RGB8 欧氏距离 `sqrt(dR²+dG²+dB²)`；变量名中的 `delta_e` 不表示 CIE Lab、CIE76 或 CIEDE2000。
