# R25：精确全色域拟合与可选原生离线库

日期：2026-10-15。串行执行，未提交或推送。官方测试集、Threshold及统计口径仍未取得；所有门槛均为本地示例，不能推断官方得分。

## 从采样近似转向精确目标

R24补齐网格节点支撑后，平均误差仅三组下降，且完整拟合变慢。R25保留原DP网格、独立四LUT目标、先验、CG参数及整数精化，改为对一般三维阶段的**全部16,777,216个RGB8输入**组装H、b。不再通过随机点估计均匀全色域目标。已证明可分离的一维阶段继续使用R22的256输入整数曲线DP，其模型字节保持不变。

新增可选C++17库`jshc_full_fit`和显式方法`ls_tetra_full` / `dp_full`。库不链接到图像运行时，现有CPU/CUDA像素内核和模型格式均未修改。Python通过版本化C ABI直接读取已有连续uint8表，无需复制完整表到临时文件。CMake默认不构建该离线库；其他拟合方法也不会加载它。

四面体每行只有四个节点，任意两个有效节点的坐标差只包含三个正轴方向的子集。因此矩阵只需对角和七种正邻接，另一半由对称性恢复，即15点邻接结构。相邻R网格单元的写入只涉及其两层节点平面；按R单元奇偶分两轮，同轮各单元的写入区域互不重叠，允许OpenMP并行而不需要原子操作。

以Q16整数权重`w_q`累加`Σw_q²`、`Σw_qw'_q`及`Σw_qy`。任一H累加器至多2⁵⁶，rhs小于2⁴⁸，单通道目标平方和小于2⁴⁰，均不溢出uint64。累加与线程调度顺序无关。转换为`H/2³⁸`、`b/2²²`后，等价于每个颜色权重1/64，总权重仍为262,144，和此前分层采样的目标尺度一致。

原生整数累加器仅`11×m³×8`字节；m33为3,162,456字节，不创建完整采样坐标或每样本16对COO展开。该数字不包含输入表、Python/SciPy、CSR或进程峰值内存。整数DP网格的每个节点都是实际输入颜色，仍满足数据Hessian的`H ⪰ I/64`支撑下界。

这不是全局最优整数模型证书：后续仍有正则化、浮点CG、节点量化、有限轮整数精化及四级误差传播。精确组装的目标为未舍入的平方误差，不能等同于实际四级RGB mean/p99/max。

## 正确性与部署边界

一次阶段检查15项通过，44.26秒。新增独立检查遍历全部256³颜色，在非均匀m17网格上逐项对比原Python COO定义，H、b完全一致；单线程与四线程整数系统相同；并检查目标平方和、全部节点支撑，以及错误C ABI长度不会修改输出。真实clip-7/m33矩阵的后续21次性能执行也要求同一H、b的规范化字节SHA一致。

C ABI检查指针、长度、m、线程数、轴索引和Q16范围，捕获C++异常并返回错误。库嵌入C++源文件和头文件的组合SHA；Python拒绝ABI不符或源码不匹配的库。模型缓存另外绑定库二进制SHA、编译的OpenMP状态、源文件SHA和线程默认值。选中此方法而库缺失时明确报错，不静默切换拟合算法。调用期间输入与库应保持不变，公共拟合命令在发布前再次核对身份。

本机实际构建使用GNU 15.2 / Windows x64，C++17。OpenMP版本请求并实际使用4线程。另建OpenMP OFF、AVX2选项OFF的独立库，在PATH仅包含Conda运行目录与Windows System32、没有`E:/mingw64/bin`的新进程中完成同一真实全色域矩阵，实际1线程，整数系统及H、b与并行版本一致。MinGW运行DLL由CMake复制到库旁。其他OS、ISA和编译器尚未实测；不据此声称跨平台验收完成。

## 三种时间范围分开比较

固定clip-7/m33，每组7对AB/BA交替、独立进程，全部输入与源码SHA绑定：

| 项目 | 参考中位时间 | 候选中位时间 | 配对时间比中位数 | bootstrap 95%区间 |
|---|---:|---:|---:|---:|
| 相同全量H、b：Python COO→原生1线程 | 11.896166 s | 0.195598 s | 55.474× | 54.324–68.200 |
| 相同全量H、b：原生1→4线程 | 0.195598 s | 0.083655 s | 2.334× | 2.317–2.615 |
| 完整四表：R22采样→R25全量 | 1.926701 s | 1.918127 s | 1.128645× | 1.114160–1.221088 |

组装计时包含坐标/基函数生成及CSR转换，排除加载和hash；完整拟合包含DP网格、一维证明与拟合、首次库加载及组装、CG和整数精化，排除输入加载、导入及序列化。完整拟合两列边际中位数几乎相同；配对统计取每对比值的中位数，不能直接用两列相除。完整拟合6/7对更快，单侧符号检验p=0.0625，小样本与运行波动限制了结论强度；不承诺跨输入、跨机器的稳定加速。

宿主进程峰值工作集中位数：全量COO 264,040,448字节、原生单线程137,195,520、四线程137,392,128；完整R22拟合583,630,848、R25拟合507,236,352。均为整个子进程的OS峰值，不是单独矩阵或部署模型的内存。

对**实际通过的clip-31/m33新模型**，另作7对CPU/CUDA比较，每次进程内部3轮取中位数。CPU声明配置为AVX2 scalar-gather、16线程、整批；CUDA为batch100/block256。两者预检的100图全部235,929,600字节均与验收结果一致。普通宿主到普通宿主的100图时间中位数为CPU **88.659 ms**、CUDA **67.1277 ms**；配对CPU/CUDA比中位1.266972×，95%区间1.218762–1.407248，7/7对CUDA更快。

上述对应每图摊销均值0.886590 ms和0.671277 ms，不是独立单图延迟。CPU计时包含工作复制与四级映射；CUDA包含普通/固定页复制、H2D、四级kernel、D2H及同步。排除拟合、分配、加载、解码、编码和输出检查。配置沿用先前声明的CPU/CUDA臂，没有重新扫描或声称它们在新模型上全局最快；本机AMD 8945HX与RTX5070 Laptop也不是未公布的官方服务器。

## 剩余误差与下一步

同网格的独立单阶段对照确认，精确数据目标的收益在真实舍入输出上仍成立：clip-7/m33第一级，R22/R25未舍入RMS为0.799249/0.754386，实际原生整数输出RMS为0.862449/0.807323。clip-31/m18的对应整数RMS只从2.305140降至2.297493，说明继续增加采样不是该例主要改进方向。这些阶段指标不构成最终四级误差的可加分解。

另一个明确问题是“先无约束求解，再裁剪”没有求得箱约束最优解：clip-7/m33第一级107,811个浮点节点分量中7,021个小于0、3,158个大于255，最小值−8.9973；clip-31/m18的17,496个分量中分别1,477和1,208个越界，最小值−13.9620。裁剪后数据目标的投影梯度仍明显非零，最大单坐标二次修正位移分别约3.30与5.50。当前最终节点仍经检查为合法uint8；这是逼近质量问题，不是无效节点被提交。后续应优先研究真正的箱约束二次求解，再处理压力场景的不连续插值与节点布局。

后续[R26](r26-box-constrained-fitting.md)已实现并验收箱约束求解及精确整数目标选择；虽通过KKT及目标检查，最终四级色差并未稳定改善，因此不替换本页R25方案。

## 使用与复现

本机已执行的构建命令：

```powershell
cmake -S . -B build-fit -G 'MinGW Makefiles' `
  -DCMAKE_CXX_COMPILER=E:/mingw64/bin/c++.exe `
  -DCMAKE_MAKE_PROGRAM=E:/mingw64/bin/mingw32-make.exe `
  -DJSHC_ENABLE_FULL_FIT=ON -DJSHC_ENABLE_OPENMP=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build-fit --target jshc_full_fit --parallel 1
$env:PYTHONPATH = 'python'
$env:JSHC_FULL_FIT_LIB = (Resolve-Path build-fit/libjshc_full_fit.dll).Path
python -m lutlab fit --inputs lut1.lut256 lut2.lut256 lut3.lut256 lut4.lut256 `
  --model-dir models/my-full --m 33 --grid dp --method ls_tetra_full
```

`select --profiles dp_jitter dp_full`可按显式mean/p99/max及images/cube/both范围筛选。普通`apply`、`cube`、`verify`、`bench-models`仍只需要既有像素程序和四张模型，不需要离线库。

阶段脚本按顺序运行，无需每次编辑后重复整个批次：

```powershell
$env:PYTHONPATH = 'python;artifacts/r18-tools/python'
$env:OPENBLAS_NUM_THREADS = '1'
$env:MKL_NUM_THREADS = '1'
$env:OMP_NUM_THREADS = '1'
python scripts/r25_full_study.py --cpu build-r18-cpu/jshc.exe --cuda build-r23-gpu/jshc_gpu.exe
python scripts/r25_performance.py
python scripts/r25_capacity_study.py --cpu build-r18-cpu/jshc.exe --cuda build-r23-gpu/jshc_gpu.exe
python scripts/r25_objective_diagnosis.py --cpu build-r18-cpu/jshc.exe
python scripts/r25_box_constraint_diagnosis.py
```

OpenMP-free构建、隔离PATH检查及当前模型映射比较的完整命令在原始JSON、构建manifest和日志中。`scripts/compare_accepted_runtime.py`接受既有验收报告，可单独比较声明的CPU/CUDA配置，不必重跑整套R19矩阵。

[证据归档](../report/data/r25/README.md)包含所有模型、源码快照、失败场景、数学诊断和原始性能样本；[精度摘要](../report/data/r25/accuracy-summary.csv)与[性能摘要](../report/data/r25/paired-summary.csv)保留未舍入值。完整输入与原生二进制通过SHA追踪，不放入小型Git归档。
