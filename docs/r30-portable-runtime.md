# R30 可独立交付的 C99 像素运行时

日期：2026-10-16。新增库位于`portable/`，C接口、独立构建和嵌入示例见该目录README。现有C++/AVX2的`auto`路径不变；本阶段未宣称新C库已成为默认后端或已获得速度提升。

## 实现与语义

库不做拟合、文件/图像解码、线程调度或设备传输。四张普通SLUT v1模型仍各自保有m³个RGB8节点及权威Q16轴表，每一级整数舍入后进入下一级。调用者持有原始模型和准备工作区；像素路径无堆分配、I/O或浮点运算。支持行步长、非对齐字节、矩形分块、原地处理，以及写入前的容量/溢出/重叠校验。模型、工作区和链在使用期间保持只读。

准备阶段完整检查存储节点，证明常量、单轴可分离和全轴0/65536分数条件后，分别选择常量、三张256项RGB贡献表、单节点读取；否则走通用四面体。下一阶段的单节点路径还可依据上一阶段全部存储节点输出集合证明。可分离与阶梯条件可能同时满足，曲线路径优先；这些捷径不合并四级LUT，也不改变任一级输出字节。强制通用模式用于同模型等价比较。

本机64位ABI每模型工作区3128字节、链48字节，四模型总工作区12560字节，另计调用栈及图像块。四个m33序列化模型共448252字节，可放只读存储；不另复制原始节点。原始四张RGB8完整表为201326592字节。3072字节/模型的贡献表是运行时缓存，必须计入RAM；不是免费的压缩。

## 已完成的集中验收

`scripts/r30_portable_stage.py`结果`artifacts/r30-portable/stage.json`为pass：

- clip-7/m17、film-11/m18、R27 stress-13/m33各穷举256³输入；C快捷与C通用的完整输出SHA均与既有实际原生CPU结果一致。复用旧CPU证据时核对了模型、底层JSON和输出哈希，未重跑旧原生像素测试。
- 5个构造批次各66391种唯一颜色与独立uint64重心权重oracle一致，覆盖混合m、非均匀m26、非单调权威索引、0/半位/65536分数、通道置换/共享轴、常量和耦合节点。
- 15项接口合同检查覆盖非对齐、行填充、行列分块、原地、空区域、容量/步长、尺寸溢出、部分重叠、模型/链/工作区重叠及错误选项。12个畸形SLUT在C与Python均拒绝，错误时准备输出保持不变。其余图片容器和完整LUT夹具不由这个无I/O库消费，仍需主入口另行验收。
- Clang21.1以`-ffreestanding -fno-builtin -Werror`编译Cortex-M4、AArch64小端/大端、RV32IM；目标对象分别4012/5008/5136/6064字节。这是对象文件长度，不能当作最终固件Flash或运行RAM。

首轮验收在R27路径预期断言处停止：第二级同时被证明可分离与阶梯，代码正确优先走曲线。修正验收期望为“曲线、曲线、节点、通用”，保留原失败记录，并在确认库字节、C源和FFI/oracle函数AST不变后复用已完成的两份全色域结果。第三组与交叉编译实际继续完成，未删除失败记录。

原生对象未解析符号只有`memcpy`与`memset`；Cortex-M4对象为对应ARM EABI内存辅助函数。裸机需由板级运行时提供这些函数。Windows DLL自身还带CRT启动导入，不能把整个DLL导入表等同于核心像素函数的依赖。

## 当前边界

R30证明本机执行与目标交叉编译，不证明真实手机/MCU执行、NEON加速、设备性能或功耗。后续R31另以用户态ARM模拟器补执行证据，与实体硬件成绩分开。当前没有新C库的配对计时结论；嵌入者还需实现正式容器适配、图像规格检查和调用者侧调度。

R31模拟执行已完成：QEMU10.2.1在WSL Ubuntu26.04 x86_64上实际执行AArch64小端/大端的静态ELF。直接链接R30已经冻结的目标对象；测试壳只提供Linux write/exit和内存辅助函数，使用6KiB像素块缓冲，不需要ARM libc或sysroot。3组模型×2种端序×2条路径共12个完整输出流、201326592次颜色求值，均匹配原生冻结SHA。ELF借用的模型字节故意放在非对齐地址。原始RGB流经管道增量哈希，不保留600MiB输出副本。复现见`scripts/r31_arm_execution.py`与`portable/verify_aarch64.c`；完整记录为`artifacts/r31-arm-execution/stage.json`。这仍不是实体ARM执行或性能证据。
