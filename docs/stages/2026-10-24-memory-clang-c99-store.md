# 16题：同一C99源码的通用x64编译器试验

保持已验8像素store C99源码、8bit ROM和原GCC验证/OMP/AVX2对象，只将store映射函数改用Clang21.1.0编译。四个新进程、同场GCC/Clang与78/80、五遍完整百图的四组A/A全部有效。Clang最差吞吐保留为原地1线程60.7600%、原地4线程65.3573%、分离1线程59.4025%、分离4线程55.8676%，全部达到50%底线；精度和逐图输出保持100%，常驻16,779,328 B，比固定78/80的28,046,644 B少40.17%。

这是编译器生成代码的独立试验，不改算法/ISA门槛，不与3B/17bit字典叠加，也没有把旧GCC四线程分离51.23%拼入本轮。当前同场GCC原地单线程最差49.4184%，其中位51.4685%不能当作通过。

## 同源、工具链与ISA

唯一新编译源码是`experiments/memory-rom/memory_rom_store.c`，SHA `e9a116e3a0b03242d01a90ebc8eee905947120e48cad030aede65cc71c772a10`，与旧GCC阶段相同。标准C99仍先读完8个输入/ID，前7项memcpy4、末项memcpy3、短尾逐像素3字节；ROM借用、原地/分离、重叠拒绝与LE字节解释均未改。

冻结计划d764ffd3绑定源码、Clang/GCC/G++二进制和全部旧对象SHA。实际编译参数为`--target=x86_64-w64-windows-gnu --sysroot=E:/mingw64 -std=c99 -pedantic-errors -O3 -march=x86-64 -mtune=generic -mno-avx -mno-avx2 -mno-avx512f`，没有native或LTO。Clang版本banner的默认target是MSVC，实际命令显式选GNU ABI和MinGW头文件；这种显式target/sysroot配置参照[Clang官方说明](https://clang.llvm.org/docs/CrossCompilation.html)。

其余9个旧GCC对象，包括验证/准备C99、OMP适配器、5个旧AVX2和2个旧ANDN对象，按旧链接顺序原字节复用。新桌面DLL为`442bc4243920280480807e4e291dff3aa2ffbdb87a0edd4407affad90578c723`；与旧控制使用不同主DLL名字，另以GetModuleFileNameW验证实际载入路径，防止同名模块混淆。

新Clang store对象的机器码仅含普通整数x64指令，核验无AVX/BMI/AVX512；整个桌面DLL仍包含供kernel1使用的旧像素对象。此处实测kernel0运行C99映射。独立C99 DLL只链接旧C99验证对象与新Clang store，不依赖C++/OpenMP；PE导入为Windows系统CRT/KERNEL32。C99映射函数本身零堆，DLL运行库启动不作为零进程堆声明。

## 内存、可移植边界和证据

ROM仍为16,778,272 B，模型1056 B，磁盘payload与常驻容量均未因换编译器改变。C99映射零堆/无逐图片缓冲，Clang静态栈120 B，旧GCC为144 B。4线程性能由GCC桌面OMP适配器提供；独立C99 DLL仅完成了正确性验收，没有单独测其吞吐，不能把桌面4线程结果称为C99自带多线程。裸机/其它CPU速度未测。
