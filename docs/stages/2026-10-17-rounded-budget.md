# 真实舍入预算统计与联合辅助排序

承接PR21的v3：Lomo/Velvia尾部缺口6817/2097，完整域SSE预算余量仅14/153；连续辅助代理可能不能可靠区分实际舍入后的预算释放能力。本阶段保留m33原轴表、原混合初态及全部101组阈值和保护，比较连续代理与真实舍入预算排序。

对每个节点、每通道±1，按实际Q16累加/RGB8舍入，遍历完整256³颜色并保留各图片重复频率，整数累计精确SSE变化及Q24距离上界和变化。后者是整数上界归约的精确变化，不是无理数mean的精确值。辅助排序检查全部逐图/聚合/完整域预算；均值比例先用Python整数求整除上限，避免Q24交叉乘法溢出。float64仅用于预算排序。

两个节点的单改变化在输出支撑不相交时可相加。新路径用“任一轴节点坐标差大于1”给出充分的单级支撑不相交证书；未获证书不等于存在交互，也不排除该候选。重叠组合可能因舍入产生交互，必须整对真实重放。逐图mean的原/初态直方图相等豁免也仍由真实保护判定，预算排序不得代替接受。

预冻结两臂：`rounded-budget-control-v1.json`及`rounded-budget-exact-v1.json`，都从v3重放24/44个累计接受步骤，SHA绑定同一检查点。每例最多新增32步、两轮辅助，各最多128主候选、保留8主×16辅助；均不增加全局排序轮次。新方案同时改动单改统计和全部预算排序，不能把收益全归于舍入精确性单个组件。只对最终变化模型做一次完整256³/100图/整数oracle/标量AVX2，不变复用v3，不覆盖旧测量。

验证预限定为3个新合同（所有单改SSE/Q24对独立整数展开与内存拒绝、重叠舍入不具可加性的真实反例、公开联合补偿路径），加2个受影响的既有连续补偿合同，集中一次。环境沿用Windows11 / Ryzen9 8945HX / Python3.12.14 / NumPy1.26.4 / Numba0.60.0，研究内部Numba4、BLAS/MKL/OMP单线程，统计归约串行；GCC15.2 Release标量/AVX2单线程终验。目的为预算正确性、对照精度和误差原因，不测性能。
