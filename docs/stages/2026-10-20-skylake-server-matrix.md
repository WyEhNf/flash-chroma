# 四后端同场比较：缓存通过本机门槛，组合仍有退化样本

Agent：Codex；Operator：WyEhNf；Task：直接比较原实现、无损坐标差、精确缓存及其组合，为Skylake准备统一入口；Status：Completed（本轮矩阵完成，目标服务器与整体优化仍In Progress）。

本轮第一次在同一协议下直接比较四个后端，避免把此前不同阶段的百分比相乘。输出全部一致。缓存单独启用通过四种场景的本机门槛；组合方案的配对中位耗时较原版下降约55%–63%，但一个四线程整批进程明显退化，按预定门槛不能全面采用。所有异常样本保留，没有重测、删样本或更换聚合方法。实际机器是AMD的WSL2，仍不是Skylake成绩。

## 改了哪些东西

没有改动原生内核、模型或拟合。四个后端分别复用修订2/5/4/6，静态停止的修订7不进入比较。

- `export_skylake_cache_gold.py`用已有独立uint64 oracle生成全部缓存槽的预期，只执行一次，不调用原生内核。
- `prepare_skylake_matrix.py`复用此前固定模型、100图原始字节和完整预期流，核对逐图像素哈希；为两组原生构建生成派生计划，原生源码与上游已验计划逐字节相同。旧计划不改写。
- `run_skylake_matrix.py`在Linux独立构建四库，先集中验证，再显式执行唯一320轮同场比较。两个同名参考库以绝对路径加载并核对实际映射，不把它们混为一库。
- `skylake_server_support.py`补记所选各CPU信息、只读缓存全表身份，并解码`/proc/self/maps`的八进制路径转义。本次输出目录实际含空格，四库及计时器均已正确识别。
- `archive_skylake_matrix.py`只读取现有回执、复算门槛和归档，不加载原生库或再次计时。首次归档把总结果中的验证策略SHA误当成性能策略SHA而拒绝，纠正归档器字段理解后通过；实验数据、冻结入口和原始结果均未改动。

阶段代码、说明及证据作为同一工作分支提交进入Draft PR #43；具体提交由Git日志和PR提交页给出。公共默认、冠军、CLI/GUI/C99和AGENTS.md不变。

## 集中正确性证明

先完成8个有限夹具×11种长度×4库×3后端/线程配置×4偏移，共4224次独立整数预期比较，包含端点65536、差值编码回退、尾部及4096块边界；另有64条布局诊断失败保护。随后四库各自单级/四级、标量1线程及AVX2的1/4线程，合计24组完整256³，均直接逐字节相等。两种调度与两种线程下共16组100图SHA一致；驱动14个非法参数样例均先拒绝，回调失败会中止。零输出差异、零哨兵差异。

实际缓存两库均为185600槽，其中171056合法、14544非法槽为零；整个742400字节u32表与独立uint64导出逐字节哈希一致：`f223e56756ed281372b0ebd858b254110c04ca1f5b2afb6d091c40df3a1ffe90`。差值库实际布局为`[2,1,1,1]`。实际四级模型核算容量依次1058292、1055220、1800836、1797764字节；坐标差每模型省3072字节，缓存仍增加742544字节，建表临时556800字节释放。整个worker峰值RSS约491844–492452 KiB，含450MiB照片源/工作区及四库，不能代替模型容量。

没有新拟合或模型精度验收。输出身份保持原单级SHA `7837c93f7b177a93e4bfb9afe8381e22eb24bdcca16009d6042e5f5b840ff146`、四级SHA `3c9ce8d98d8db454ce9337c50c2ecadb8ba59485d6bc3e6a42e3cc1dfe307c22`；复用既有RGB欧氏距离结果，不称CIEDE2000或新增官方精度通过。
