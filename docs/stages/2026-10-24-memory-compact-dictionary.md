# 16题：精确16B字典的3B与17bit索引

第七独立阶段保持共同a399四级模型和所有RGB8输出，压缩首阶段16B字典的块索引，不叠加RGB24通用句柄或root的有损palette研究。原字典有1,048,576项32bit绝对偏移和107,707个16B块；块池只有1,723,312 B，偏移全在24bit内，块编号也只需17bit。

## 格式、解码与生命周期

独立实验ROM名为M16P，版本1，固定16B块，header标记entry_bits=24或17，不修改原SLUT/M16D。palette/header固定1056 B，保留完整230项合法调色板；没有只保留完整域实际命中项而截断合法元数据。

3B格式把旧偏移减去索引表缩短的1MiB，逐项保存LE24绝对偏移。17bit格式保存紧密LE位流块编号，解码`bit=17*block`，读取三个字节后按`bit&7`右移、mask17、乘16并加固定pool基址。最多移7位，因此17+7=24位，C99不需64bit加载或跨界第四字节。

C99核心显式LE字节拼装，零堆、无浮点、不需ROM对齐。桌面AVX2循环由首阶段同源快照生成，只替换ID查找：memcpy4读取并mask/shift。最末索引项多读的一个字节落在格式要求非空且owned的pool首字节中，不要求调用者额外padding；pool仍按字节索引。两个固定格式分别编译，避免逐像素模式分支。没有AVX512或新BMI需求，只有像素TU启用AVX2。

prepare验证长度、调色板、全部1,048,576个索引的范围与16B对齐和pool内每个ID，成功后借用不可变ROM，调用者保持其生命周期。失败清零句柄；句柄与ROM重叠时无写拒绝。结构布局保留1056 B以复用Python适配器，但log2_block字段在M16P内部为entry_bits，不能拿旧M16D句柄混用。

## 完整域、拒绝和边界

- 导出仅读取已冻结M16D字典，不读照片/gold/原滤镜。两格式分别独立重建全部16MiB逻辑ID流，SHA均为`a020c67a0e8ce77e668e6c6d85206af53005923316b4778194637182b4cfaea0`。
- 两格式各自通过独立C99、桌面scalar、AVX2 1及4线程完整256³ RGB输入，共8次完整域，四级输出SHA全部为`3c9ce8d98d8db454ce9337c50c2ecadb8ba59485d6bc3e6a42e3cc1dfe307c22`。
- 720组有限形状覆盖长度0/1/7/8/9/15/16/17/31/32/33/73/4095/4096/4097，原地/分离、源/目标偏移0/1/3/7和三后端，对比独立C99及首尾哨兵；另4组验证prepare重叠无写和两格式坏索引拒绝清零。
- 原派生合同另有124组图片保护页/非对齐ROM比较和23个格式/IO范围拒绝。该124组并不表示整个ROM尾部紧贴保护页。
- 为这个差别另补8组ROM末端保护页：整个ROM后紧贴PAGE_NOACCESS，选原字典偏移最大的块末像素，强制读取pool最后字节；两格式原地/分离1/4线程均与独立C99相等。保留原124组原件，新增单独脚本/结果。

因此相对a399的mean/p99/max和逐图误差原值不变，精度保留100%；全域误差仍mean0.9811105967、p993.7416573868、max8.1240384046，不是相对原滤镜零误差。所测桌面DLL SHA为`90c4081d16d4f8929247ba15af4a1a58afbc6f99246ccb95ddf35a8b9db33a6d`，候选运行源在冻结后未修改。

## 旧控制的跨场差异及确认要求

本轮dict32确实加载首阶段原DLL，build回执、首阶段四worker、当前四worker和磁盘SHA全部为`88bddba254d4ad7755778c2c24a6a5660af1d463704db90c556b7889e28d57f6`；ROM SHA也与首场相同，没有重编译或用新loop替换旧控制。旧AVX2源SHA为`0fff326ae0532f9f9cacaf82cc38f37acad56692d0dcdb9959b1a0179cef3b8e`，与既有发布源码ZIP逐字节一致，旧对象SHA为`abbceff32bec4c81d4ce65d6adacc664bf6342dbe59db52837871c5c6983f62d`。
