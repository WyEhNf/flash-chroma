## 做了哪些工作

`scripts/prepare_skylake_server.py`在现有Windows环境导出字节包。每张照片先核对原编码及解码像素SHA，原样串接，无新增缩放或调色；8种既有边界模型另用独立uint64 oracle导出4097像素预期，覆盖所有码值、8角点及固定随机输入。模型、原照片清单和完整预期流沿用原哈希。准备过程没有原生像素、拟合或性能调用。素材用途限制随原清单保留，不声明新许可。

`scripts/run_skylake_server.py`是Linux x86_64统一入口，只依赖Python标准库、CMake、GNU C/C++和OpenMP。先检查全部包字节与SKU可选约束，按允许CPU集合选择同L3/NUMA的4个不同物理核，再独立构建参考、候选及计时器。计时进程显式设置OpenMP places与close绑定，清除相互冲突的线程环境，核验实际团队CPU和唯一libgomp映射。记录CPU原文、微码、GDS缓解、编译器/库路径及SHA；不修改系统安全设置、频率或安装依赖。

`experiments/skylake-server-driver`提供独立原生计时器，用与已有`jshc_cc_apply`完全相同的函数指针类型调用真实C ABI。每轮先复制源，分别记录apply、copy+apply和100图外层墙钟。整批模式调用一次235929600字节；逐图模式调用100次2359296字节，保留每图调用区间及尾部统计。循环内不分配、不哈希、不读文件。边界参数、整数溢出和源/工作区/时间数组重叠会在执行前拒绝，回调失败终止整组。

正式比较必须显式加`--measure`，先绑定同一构建的完整正确性回执才启动：4个串行新进程AB/BA/BA/AB，线程及两种调用模式顺序平衡，每配置5轮，共160轮100图组。每进程中位后配对，再聚合四个比；两线程档、两种模式分别要求apply中位至少改善3%、任一进程不得回退超过2%、copy+apply中位不退化。保留全部轮次、准备墙钟、模型容量和整个进程峰值RSS，二者不混用。不因失败自动重试或改门槛。

`scripts/skylake_server_support.py`集中处理标准库绑定、拓扑、库来源和回执校验；已有`verify_skylake_linux_stdlib.py`只补充可选固定CPU及准确的实际Linux环境表述，原数值比较逻辑未改。历史WSL回执仍绑定原源码ZIP，未改写旧结果。AGENTS.md及公共核心、CLI/GUI/C99和默认模型未变。

## 一次集中验证

目的为新入口的独立构建、Linux代码生成正确性、边界保护及两种调用调度正确性，不做Linux性能选型。实际环境同一AMD Ryzen9 8945HX主机的WSL2 Ubuntu，Linux6.18.33.2-microsoft-standard-WSL2、glibc2.43、GCC15.2.0-16ubuntu1、CMake4.2.3、Python3.14.4标准库；客体报告4物理核CPU0/2/4/6同L3，探针团队1/4实际分别为CPU0与0/2/4/6。GDS报告`Not affected`，不能推断Intel服务器状态。AVX2 TU仍为`-mavx2 -mtune=skylake -ffp-contract=off`，计时器为普通ISA，不含AVX2或fast-math。

- 两库单级/四级、标量1与AVX2请求1/4共12组256³直接字节比较全部一致，另有528次实际模型有限后端/偏移比较。完整预期来自此前独立整数oracle与完整流，本脚本不重新计算Linux独立oracle。
- 8种差值/回退/混合布局×11长度×2库×3后端线程组合×4偏移共2112次，与新冻结的独立uint64预期直接逐字节一致，哨兵不变；32条只读诊断失败保护通过，逐布局容量减少量等于压缩级数×3072字节。
- 两库×1/4线程×整批/逐图共8组100图，输出SHA均复现`f3c0d9078bbcf069f33060a45021a28985b70c9616493ba9bea1ac2027858528`；14条原生计时器参数/重叠/溢出拒绝保持输入和时间数组不变，回调失败正确中止。此阶段计时器返回的区间仅检查合法性，没有用于加速比较。
- 实际Linux模型容量参考1058292、候选1055220字节，和Windows相同，仍非RSS。两Linux主库与依赖实际映射SHA另存，完整输出SHA复现既有结果，不新增拟合精度结论。

初稿计时器回调的句柄声明使用了`const void*`，与现有C ABI的`void*`不完全一致。最终源码已对齐，并加入编译期`static_assert`核对函数指针类型。修正前后独立编译的对象和共享库均逐字节相同：共享库SHA为`b9a37fa74a2b454a274a7a38c19a4e34546b495e288e549bbae5b6395c354b75`。因此复用同一机器码的上述验证，没有重跑不受影响的完整色域；原稿、最终源码、两次对象及相等证明均保留。建议复现最终v2字节包，不使用初稿声明。

## 复现与证据

本地最终包为`artifacts/skylake-server-bundle-v2.zip`，188256487字节；包内88项文件共约338MB。清单SHA为`2118b42b093e4a46e04de56e47c47d0a74bba496b53acb8ff30635a19d85d777`。原始像素及全色域流没有提交Git；仓库仅保存[清单、构建、源代码、二进制及正确性回执](../../report/data/skylake-server-entry-v1/README.md)，ZIP的完整SHA见`final-bundle.json`。没有上传服务器或取得服务器连接入口。

在Linux解包并进入目录：

```sh
python3 scripts/run_skylake_server.py --bundle bundle-manifest.json --output artifacts/server-run-v1 --compiler /usr/bin/g++ --c-compiler /usr/bin/gcc --measure
```

省略`--measure`执行本阶段已验证的正确性流程。可指定`--cpus 0,2,4,6`，须通过实际拓扑检查；`--expected-cpu`必须与`/proc/cpuinfo`中型号原文一致，不能只给“Skylake”。输入/源码/库哈希与命令由包及结果逐层绑定，输出目录必须全新。准备命令、初稿到最终包的只读复用脚本和源码原字节在归档中，复现时不依赖Git换行归一化。

正式四进程性能分支未在本机WSL运行，其最终编排及采用门槛仍须在目标服务器执行；本阶段不能称服务器性能已验收。整批摊销毫秒/图与逐图C ABI调用延迟分开，逐图p99是重复固定照片的描述统计，不是独立随机请求尾延迟。新入口包含公开C ABI成本，不能与旧内部bench绝对时间混用；OpenMP绑定也不同于旧Windows测试。
