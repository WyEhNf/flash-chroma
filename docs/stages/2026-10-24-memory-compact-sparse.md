# 16题：通用冻结稀疏句柄的无损容量优化

本阶段在普通四级模型上将实际常驻容量从specialized v2的487,737 B降为268,308 B，减少44.99%。四个独立进程、每进程五轮完整百图的最差吞吐保留为单线程97.21%、四线程92.86%，四组A/A控制全部有效，进入90%档。该结论仅对应下述一般模型，不能替代Cinema最优直表。

共同a399模型的句柄也从1,058,292 B降至594,072 B，减少43.86%，但相对同场最快78/80仅保留3.40%和3.46%吞吐，低于50%底线。该用途明确拒绝；相对较慢specialized的接近持平不能用来升级Cinema档位。

## 表示与生命周期

原specialized同时持有SLUT的canonical RGB8节点、packed RGB32节点、轴数组与原侧表。独立研究库逐级调用既有SLUT加载器并完成元数据/坐标单调性/端点验证，直接生成唯一owned packed RGB32节点与768或2304个轴词。每级结束释放canonical模型和原侧表；相同的分通道轴按shared布局复用。外层向量先固定尺寸，View指针只指向之后不再移动的owned向量。

创建任一级失败时，临时句柄由RAII销毁，输出句柄保持空；成功后句柄自身持有全部运行数据，不借用输入文件缓冲。公开原库和默认路径均未改。研究库ABI仍为1，revision为1001，另增只读四项容量诊断。像素AVX2对象与specialized v2完全相同（SHA-256 `2edcc3ae0792294ebd59614c9634719869830cb839a8838c551987443afac3e4`），只重写准备/句柄和标量fallback，没有通过量化或像素改写换取容量。

这一路径支持m=17..33、1..4级、普通/分通道/shared混合轴，不依赖Cinema的230色窄域。它仍是C++17/标准库句柄，桌面并行依赖OpenMP；本阶段没有新增ISA，也没有把它宣称为前阶段的独立零堆C99核心。

## 正确性证据

- 初始有限合同1,584次对照：m=17/18/25/33，普通四级、首级分通道、混合分通道、相同侧表、普通单级和分通道两级；长度0/1/7/8/9/15/16/17/4095/4096/4097，偏移0..3，标量1线程/AVX2 1及4线程。独立uint64重心oracle和旧specialized双对照全部相等，四个非法输入拒绝。
- 初次合同没有覆盖三级，这个遗漏保留在原件中。后补shared3/mixed3的192次相同oracle对照通过，独立记录脚本SHA和库SHA。
- a399单级与实际四级在标量1线程/AVX2 1及4线程全部遍历256³ RGB输入。单级SHA为`7837c93f7b177a93e4bfb9afe8381e22eb24bdcca16009d6042e5f5b840ff146`，四级为`3c9ce8d98d8db454ce9337c50c2ecadb8ba59485d6bc3e6a42e3cc1dfe307c22`，与既有金标准相同。
- 另用seed=2026102405的随机RGB8节点、混合m四级模型完整遍历256³，对照specialized AVX2，SHA为`045b39b5f5291c826217021c1490fafdd45cd2b60a83f2e74694d91d7331b4ab`。合成节点从0..255全字节范围取样，原有限原件中“覆盖全部RGB8输出”仅指这个取值范围，不是已证明所有16M种输出均出现。
- 性能每个角色、每线程、每worker的预热与最后一轮百图均再次比对SHA。因此mean/p99/max和每张图误差都保持原值，精度保留100%；这不等于相对原滤镜零误差。a399全域原值mean=0.9811105967、p99=3.7416573868、max=8.1240384046。

## 同场吞吐与六档

冻结计划为`experiments/compact-sparse-v1.json`，四个新进程按旋转/反转顺序测compact、specialized v2、78、80；单/四线程原地RGB8，各角色预热一遍再五遍完整100张1024×768照片，拷贝恢复输入不计入apply时间。每个worker取三参考库中位耗时的最小值除以候选中位耗时，以最差worker划档。80尾部A/A单对须在[0.8,1.25]、四进程中位须在[1/1.1,1.1]。这组结果四个控制均通过。

## 重放与证据

`scripts/build_compact_sparse.py`绑定原静态core、原AVX2对象和旧specialized的SHA，`verify_compact_sparse.py`生成一般模型并执行有限/完整域合同，`check_compact_three_stage.py`保存三级补验；`bench_compact_sparse.py`执行冻结四进程协议。测量前源码哈希由计划校验，阶段结束没有修改已测运行源。

精简包在`report/data/p16-compact-sparse-v1`：原始build/finite/full/three-stage/performance JSON、全部worker与12个RSS原件、所测源码/栈记录、候选库及原AVX2对象、一般模型输入和SHA清单。大照片/完整RGB域不入库，参考库与四MinGW依赖沿用首阶段发布件，原SHA在本轮JSON中重复绑定。发布路径预先设置`-text`，入库前逐项核对Git blob/工作树/manifest的原字节。

后补定位说明：78/80与四依赖具体在`report/data/p16-memory-rom-v1/measured-libraries.zip`，specialized另在更早的`report/data/channel-runtime-specialized-v1/binaries-and-core.zip`，不是首个ROM包重复收录了specialized。只补清引用位置，保留原manifest和所有测量原件不改。
