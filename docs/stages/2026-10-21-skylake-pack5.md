# 八色五位无损直表：容量缩小但周期显著回退

Agent：Codex；Operator：WyEhNf；Task：保持完整 RGB8 精度，相对修订23达到三倍吞吐；Status：In Progress。**整体三倍目标仍未完成。** 当前已验完整墙钟最优修订40的纯映射单/四线程为2.6444/3.1200倍，真实输出为3.3066/4.3069倍。本阶段62未过事前筛查，没有新的墙钟吞吐成绩。

本阶段从[Draft PR #59](https://github.com/WyEhNf/flash-chroma/pull/59)的`cae124d1b099ff7aeeec16ee1837c0601b0767f3`开工作分支`codex/skylake-pack5-20261021`，从已验40原字节复制独立运行时，只更换16MiB无损u8调色板ID表的构造和读取。按`R | G<<8 | B<<16`地址顺序，每8个颜色保留最小ID一字节，后续8个ID相对基数各占5bit，共6字节。实际230项原调色板的2,097,152组最大跨度为26，均不需要例外；末组`memcpy`读取8字节所需的4字节保护位于同一次分配内。有效载荷12,582,912字节，计量分配12,582,916字节。若其他获证模型有跨度大于31的组，构造后释放新表并沿原23路径回退。原模型、逐级Q16/RGB8整数舍入、旧格式/回退、40的64像素NT输出、NTA输入及65536像素工作块、公共默认均保持。

只读预分析曾研究16色/11字节块，但需要独立基数读取和例外。另一Agent独立审计8色/6字节格式，在实际230项ID上完整检查全部组并解码全色域零差；该只读结论不是性能结果。旧照片的16色/11字节物理缓存行统计不能套到本次8色/6字节布局。本实现仍须用实际计数判断是否能抵消地址乘6、可变位移和ID加法。

实际构建/验证环境为Windows11宿主、Ryzen9 8945HX、WSL2 Ubuntu Linux6.18.33.2、GCC15.2、Python3.14.4。Release SIMD翻译单元为`-mavx2 -mtune=skylake -ffp-contract=off`，无AVX-512、BMI2依赖、FMA或fast-math。独立标准库核验完整16,777,216种RGB8：新表读取按Python `struct`独立解码，并同既有完整oracle逐字节比较；单级/四级各有参考/候选的标量1线程及AVX2请求1/4线程，共12组原地与12组分离输出完整配置，全部输出SHA相同。另有有限原地2208、分离/同址4416、保护页736、目标对齐1280、API拒绝44、直表拒绝9，零字节/哨兵差异。完整主体12MiB在本机实际AnonHugePages覆盖，末4字节为普通页；`fully_huge=false`如实保留。固定模型精度不下降，未重新拟合。

[构建冻结计划](../../experiments/skylake-pack5-v1.json)在首次构建前锁定69份源码SHA及格式；[计数策略v1](../../experiments/skylake-pack5-pmu-v1.json)在任何计数前因候选库相对路径与完整验证回执的绝对路径不一致而拒绝，没有产生样本。[v2](../../experiments/skylake-pack5-pmu-v2.json)仅修正该路径，保留原始门槛与顺序。相对40，事前条件仍为同场单线程周期比≤0.95且四线程≤1.05；各角色/线程一次预热、一次用户态计数，100张已见1024×768照片，完整输出SHA相同，所有计数running/enabled=1。
