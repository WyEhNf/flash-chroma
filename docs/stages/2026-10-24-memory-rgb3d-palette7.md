# 16题内存独立分支：512bank/7bit精确palette实际实现与正式拒绝

Agent：`/root/memory`；Operator：当前16题用户；Status：Failed，实际ROM/ABI与质量通过，但唯一正式场四模式全部低于50%速度底线。独立分支`codex/p16-memory-20261023`，Draft PR由root统一维护；不改原6bit失败、旧字典负例或默认。

## 依据与单版选择

[原512bank/6bit](2026-10-24-memory-rgb3d-palette6.md)完整频数证明最大95色，故6bit失败；新独立版本直接由`64<95<=128`选择固定7bit，不再普查模型或用照片挑参数。原6bit54个失败bank和最大95保持。既有完整频数支持SHA`6d51134d…`，ZIP SHA`63366451…`，原普查计划17a12d05…均绑定；这次按每bank正频数原globalID**升序**编号，不做排序、位宽、局部分区或编译器扫描。

[静态设计原件](../../experiments/rgb3d-palette7-design-v1.md)及proposed文件保留最初未实现状态；root另授实施后，单版生成器创建AVX lookup和受控bench文本，语法检查后，在任何新ROM/编译/native质量前冻结全部执行源与输入。新计划SHA **`b847f81c987476a6250d8c643cab70464f80764c7d367ed4c39cbe1fcd19f145`**。

## 实际格式与容量

固定`bank=(R>>5)|((G>>5)<<3)|((B>>5)<<6)`，仍对全部24bit输入各存独立7bit值，不是8³颜色采样近似。C7BK v1顺序为header、512项LE16 count、bitstream、零guard、512×128 LE RGB32 palette。新model四字段不可变借用ROM，不复制palette，不与旧1056B ABI混用。

| 部件 | 实际字节 |
|---|---:|
| header | 32 |
| counts | 1024 |
| 7bit直表 | 14680064 |
| 自有零guard | 4 |
| 本地RGB32 palette | 262144 |
| **ROM文件** | **14943268** |
| **实际Windows x64 ABI** | **32** |
| **常驻capacity** | **14943300** |

较旧线性8bit ROM/model16779328B少1836028B，但实测速度未保留50%，不能据此进入联合前沿。ROM SHA **`0c5ec7196bb3357ba2ad77f772c36e151a571e1fe5a0f3f363b935d3c341bea0`**，本次这些容量已由真实文件长度和native sizeof核实，不再仅为投影。ROM压缩包大小另属传输，不作RAM。

每bank count允许1..128、unused槽为零、每RGB最高byte为零；prepare核全部16M条ID在所属bank范围内。bitstream从1056开始，guard从14681120开始，palette从14681124开始；最后palette词结束于ROM末端。显式LE核心不依赖ROM对齐/主机端序或外部padding；无堆、不依赖C++/OMP。借用生命周期、格式失败清零、out/ROM重叠无写和IO别名/溢出合同沿严格旧语义。

## C99/AVX实现与已执行环境

C99用先读全8像素并计算8索引、再前7个memcpy4/末个memcpy3的已验结构，短尾每像素读3写3。源palette是序列化LE字节，同址输入不会被尚未读取的4B重叠写破坏。唯一Clang21.1严格C99 generic x64构建，`-march=x86-64 -mtune=generic -mno-avx -mno-avx2 -mno-avx512f`，反汇编核无AVX/BMI；不是重新跑GCC/Clang择优。

AVX2生成器只替换3B/M16T查找为7bit+输入bank+最终RGB，palette用byte指针与memcpy4；保留原宽输入、64像素先读后写、NTA/NT/SFENCE、输出、尾部和65536 OMP块。独立TU用GCC15.2 `-O3 -mavx2 -mtune=skylake -ffp-contract=off`，没有新增BMI、native或AVX512。桌面C99四线程需可选OMP包装；纯C99 DLL单独验收，不依赖OMP/SIMD。

实际Windows11 26200/AMD64、Ryzen9 8945HX、Python3.12.14/NumPy1.26.4，OMP/BLAS/Numba环境各1线程，native显式请求1/4。root授权非性能窗，可与其它分支质量并行；无速度或实板结论。

桌面DLL SHA **`89a325f566b3890ce335c028837407504a7bbc5f63a6888e0be1cff8d312e932`**；纯C99 DLL SHA **`0d10454be2a6f235b701e5c802c4b001ae9823d51181cb472ce606d711bfb549`**。两者和所有依赖、编译器身份在build/冻结计划中保留。

## 质量与边界

导出独立从实际序列化字节解码全部16M，与原M16D逐项RGB相等；内部RGB32摘要29a15ba4…、原ID流a020c67a…保持。新纯C99、desktop scalar、AVX2单/四线程各原地/分离共8个完整256³摘要全部 **3c9ce8d9…**；同样8配置完整100图输出摘要全部 **f3c0d907…**，照片输入摘要e13278cf…匹配。输出保持原a399误差，精度保留100%不代表相对目标滤镜零误差。

通过584项有限/非对齐/零长、58项格式与IO拒绝、144项输入/目标双保护页、24项只读ROM尾NOACCESS合同。ROM为实际、count1、count128三组，每组8后端/别名配置；count128夹具用`(R&31)|((G&3)<<5)`覆盖全部512×128合法槽，ffffff命中bank511/local127/ROM最后palette词。7bit的0..7八种起点、末bitstream到明确guard、最大RGB、各轴跨bank、短尾/同址等均覆盖；没有用合法槽最高ID取代实际色数或截短原模型palette。

Clang `.su`：prepare32B、validate_io16B、apply176B；GCC AVX分离入口272B。它们是各函数静态帧，不是调用链、OMP线程或MCU的总栈。尚未执行WASM、ARM/RISC-V/大端对象或实板，源码显式LE不等于已运行这些目标。
