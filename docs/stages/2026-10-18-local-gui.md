# 本地色彩工作台 GUI

本阶段为项目提供可直接操作的本地浏览器界面。入口为 `python -m lutlab gui`，或 Linux/Pixi 中的 `pixi run --locked gui`。默认仅监听 `127.0.0.1:8765`，自动打开浏览器；端口和输出目录可配置，不需要 Node.js、前端构建或新增 Python 依赖。

## 可以完成的工作

- 从项目照片库选择图片，或上传最多 400 万像素的图片；按 EXIF 方向转正、转 RGB，不应用 ICC 色彩管理、不自动缩放。1024×768 为题目尺寸，其他尺寸标为预览。
- 配置四级独立 LUT，支持导入项目的 `.lut256` 完整 RGB8 表和 `.slut` 模型，内置自然暖调、冷青电影和恒等数值示例。完整表为 B 最快的 R/G/B 索引，精确大小 50,331,648 字节；现阶段不直接导入 `.cube`、`.3dl`、Hald TIFF。
- 对完整表选择 m=17..33、均匀/曲率网格，以及直接采样、四面体最小二乘整数精化、分层采样整数精化。调用现有 `fit.fit_model`；已有稀疏模型保留自身 m、节点和权威 Q16 表。拟合在后台串行执行，一次只运行一个任务。
- 使用现有 NumPy Q16 四面体映射，或显式指定已构建的原生 CPU 运行时（auto、4线程）；后者调用既有 `runtime.apply`，不虚构实际 SIMD 状态。
- 拖动分割线比较原图/结果，查看当前完整图片的 mean/RMS/p99/max、CVaR1%、自定义阈值超限比例、最坏像素位置及误差热图。全部四级都具有完整参考时才计算误差；导入任一无完整源的 `.slut` 后显示无参考，不拿原图充当黄金真值。
- 查看实际节点的三维抽样、节点/序列化容量、本次运行记录；下载输出 PNG，以及含输入/输出/模型/报告和可用参考/热图的 ZIP。产物按会话和任务隔离在 `artifacts/gui/`，不覆盖旧研究记录。

主文件为 `python/lutlab/gui.py`、`python/lutlab/gui_web/`，统一命令路由在 `entry.py`，Pixi 新增 `gui` 任务；`tests/test_gui.py` 检查 GUI 接入和 HTTP 边界。本页、README 和文档索引说明使用方法与限制。AGENTS.md 只读，核心拟合器、插值器及硬件代码未改。

## 启动

```bash
pixi run --locked gui
# 或在已有 NumPy、SciPy、Pillow 的环境中：
PYTHONPATH=python python -m lutlab gui --no-browser --port 8765
# 可选原生 CPU：
PYTHONPATH=python python -m lutlab gui --executable build/jshc
```

Windows PowerShell 使用已有 Python 环境：

```powershell
$env:PYTHONPATH='python'
artifacts/error-study-py312/Scripts/python.exe -m lutlab gui `
  --executable build-engineering-alignment/jshc.exe
```

浏览器关闭不会取消后台任务；停止服务结束会话，结果文件继续保留。新启动不会在界面自动加载旧会话历史。单会话最多 32 份上传、50 次任务，每份上传最多 64 MiB。使用不透明资源 ID 和明确文件清单提供内容；只允许本机 Host，写操作校验会话 token 与 Origin。

## 阶段验证计划与边界

测试目的为 GUI 接入正确性、完整参考口径、输入保护和浏览器交互，不评价算法精度增益或性能。先完成实现，再集中一次运行 3 项接入验收：HTTP 导入混合 m/非均匀轴的四级模型，对独立标量整数 oracle 及导出轴表；解析常量完整 LUT 的黄金输出与零误差；会话校验、非法格式/参数及路径拒绝。复用原拟合/映射算法，不新增全色域和 100 图扫描。

另在浏览器完成一次现有 1024×768 照片的合成示例流程，检查分割对比、热图、配置、历史和下载入口，查看桌面与窄屏布局。需要时仅针对实际失败修复复验。正式验收前记录操作系统、CPU、解释器和依赖、浏览器及原生程序身份；实际结果随后补入本页。

本工作台统计仅针对当前图片；交互用时包含拟合等步骤，不是公平性能基准。RGB 欧氏距离不是 CIEDE2000；观察阈值由用户填写，不代替尚未取得的官方 Threshold。示例为可复现的数值映射，不是自然 ISP 或比赛成绩；不升级默认拟合器/冠军。

## 实际验收结果

环境为 Windows 11 10.0.26200 x64、Ryzen 9 8945HX（16核32线程）、Python 3.12.14、NumPy 1.26.4、SciPy 1.15.2、Pillow 10.4.0；OPENBLAS/MKL/OMP 均设为 1。界面使用 Codex 内置浏览器，接口未提供引擎版本号。没有新增编译；原生比对复用 GCC15.2 Release 程序，SHA 为 `ba088c682bb2b0e2e4634b23b35e662c52d87d38806d05827b876f08c8697f3a`。

- 接入合同首轮 **3/3通过（5.43秒）**。增加刷新后会话恢复后，对四级 HTTP/独立整数 oracle/导出/恢复的同一项定向复验 **1/1通过（2.02秒）**。整组复核 **3/3通过（3.75秒）**。随后审查发现准备阶段异常可能使任务无法结束，修复后对既有输入保护项追加失败状态断言，定向 **1/1通过（1.53秒）**；日志保留各轮，合计仍为三项合同，不把重复执行数当用例数。均无跳过或警告。原生完整门禁和历史117项未在本机重跑。
- 1024×768 Kodak `kodim03` 的四级暖调示例成功：当前图片 mean=1.1356、RMS=1.3817、p99=3.3166、max=5.4772。它们是示例值，不是优化收益。使用已生成的同字节模型和输入额外执行一次原生 CPU auto/4线程，与 NumPy 输出解码后的 RGB8 像素差异为 **0字节**；未重新拟合，也未做计时循环。apply 回执没有报告解析后的具体内核，不能据此单列 AVX2 收益。
- 浏览器已实操示例、分割滑块、结果/热图切换、素材检索（`kodim` 返回5张）、运行记录和结果恢复、页面刷新后恢复、ZIP 下载；浏览器错误日志为空。1440×1080 与390×844视口均目视检查并无横向溢出，临时视口已恢复。验收中发现并修复默认阈值的 step/min 不匹配、窄屏导航不可达、指标卡横向溢出及桌面预览对齐问题。
- 整组复核及随后错误处理修复的源码指纹分别记录，合同日志、像素比对和桌面/窄屏截图见[本阶段证据](../../report/data/gui-v1/README.md)。最后修复只移动异常边界和保证失败回报，映射公式未改。示例 ZIP 和 PNG 保留本地，不覆盖旧数据；没有执行新的全色域、100图、GPU或实板实验。最小二乘/曲率仍调用既有实现，本轮未逐项重测这些算法的精度或耗时。
