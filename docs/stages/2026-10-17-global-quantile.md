# 全观测颜色截断下界与候选覆盖修复

承接PR20，Lomo在缺口7636处有限库停滞，Velvia缺口3616但只到32步上限。Lomo反事实已显示热点外辅助节点单改可行，不能把零接受归为表示极限。本阶段保持原m33轴表、原混合初态和全部101组预算，改善主提案覆盖；不做新网格、权重或硬件矩阵。

对一个阈值条件，令x=max(d²−t,0)，允许B个像素处于尾部，当前代价是N−B个最小x的和。固定当前截断点u时，`sum(min(x,u))-B*u`是代价下界，并在当前模型取等；当前无缺口取u=0。用所有颜色及逐图频率，对全部节点单通道±1的真实RGB8变化累计此下界，不只查看64个热点。平方误差改变和排序全用整数，负下界只是必要候选条件，不保证真实缺口下降或mean/RMS可行。逐次真实单候选验收额外检查下界关系，双节点代理相加仅排序。

有限冻结范围：从v2模型重放20/32个累计接受步骤并核对模型/完整流SHA；每例再至多32个接受步骤。原热点搜索停滞后最多两次全节点排序，各最多128单节点及16不同节点120对，必要时最多两轮原RMS辅助补偿。记录候选来源与下界/实际缺口/拒绝原因；普通热点延续收益不得归功于全局排序。每例仅最终变化模型做一次全域/100图/整数oracle/标量AVX2终验；不变复用。缺口零才满足全部冻结条件，有限库停滞不证明全局无解。

阶段测试预先限定：两项全局排序合同（独立逐像素频率展开与真实损失下界；真实热点外节点反例），以及受改动公开搜索路径的两个既有补偿合同，完成后一次集中测试。研究环境预计与PR20相同：Windows11 / Ryzen9 8945HX / Python3.12.14 / NumPy1.26.4 / Numba0.60.0，研究Numba4、BLAS/MKL/OMP单线程，整数排序归约为串行；GCC15.2 Release标量/AVX2终验单线程。目的为覆盖、下界、事务和精度，不测性能。计划见`experiments/quantile-tail-v3.json`；实际环境和源码身份随执行冻结。

## 已执行结果与候选来源

## 截断下界的误差来源

四次全局排序分别有3300/3141、3301/3201个负下界单提案；实际只试3/6、21/11个即接受。试探时逐个断言真实缺口变化不小于整数下界。代理松弛仍明显，Velvia被试的单提案最大松弛923。

新增局部归因入口`scripts/diagnose_quantile_bounds.py`，源码先冻结于`b40f2c8`，只重放本轮16个已接受修改。合并其受影响支撑，读取80完整图片及既定选择样本频数，不用20审计反馈；初态局部整数输出与旧完整流一致，每步模型SHA与冻结检查点一致，最终101组直方图与完整验收完全相同。

每个条件独立计算旧缺口、冻结截断u、代理变化和真实新缺口。按旧缺口为0或正，将松弛分为新激活条件、已有活跃条件的截断变化；各条件松弛均非负，并精确复现保存的全局分数。

| LUT/累计步骤 | 下界变化 | 真实缺口变化 | 新激活条件松弛 | 活跃截断松弛 |
| --- | ---: | ---: | ---: | ---: |
| Lomo 21 | −802 | −73 | 0 | 729 |
| Lomo 23 | −666 | −666 | 0 | 0 |
| Velvia 39 | −278 | −5 | 130 | 143 |
| Velvia 41 | −346 | −8 | 0 | 338 |

所以本阶段不仅确认热点覆盖不足，也定位了下界排序的乐观误差：u被冻结后，排名/截断变化及原来满足的条件被破坏，都不能从线性代理直接看出。本轮真实重算避免误接受；后续应优先改善有限候选真实代价排序、利用SSE补偿余量，不能简单把负下界当作收益预测。
