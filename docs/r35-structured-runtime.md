# R35：结构证明接入原生 C99 与 AVX2 后端

本轮把已通过 R30/R31 的 C99 引擎接入桌面统一入口，并将相同的完整节点与前缀集合证明用于新的 AVX2 内核。新后端的阶段正确性已经验收；当前仍有独立拟合进程运行，本轮没有性能比较，也不据此修改默认内核。

## 实际可用的接口

- `tetra_c99`：原生命令行通过现有 C99 库执行四级映射，使用已有 OpenMP 分块调度；关闭 OpenMP 时单线程运行。
- `tetra_structured_avx2`：一次处理 8 个像素，四级数据保持在寄存器中；按已证明的常量、曲线、节点、通用四面体路径执行。
- `python -m lutlab plan --models a.slut b.slut c.slut d.slut --executable build/jshc --kernel tetra_c99`：读取真实原生计划，报告每级路径、证明标志、前缀节点条件及模型内存。Windows 执行文件名加 `.exe`。

两个新内核要求恰好四张、17≤m≤33 的 Q16 模型。不支持的构建或尺寸明确报错，不静默切换算法。原来的 `portable`/`tetra_portable` 别名保留其标量含义，新 C99 后端使用明确名称 `tetra_c99`。

现有 `apply`、`cube`、`verify`、`bench-models`、`validate` 通过 `--kernel` 选择新内核。公共 Python `plan` 入口已实际执行，记录在本轮 `public-plan.json`。构建选项 `JSHC_ENABLE_PORTABLE_C=ON` 默认启用；关闭后仍可只用 C++ 编译器构建原有后端。

## 路由与精确性

所有路径先检查完整 m³ 节点，不根据几张图片猜结构。曲线路径要求每个输出通道最多依赖一个输入轴，允许多个通道依赖同一轴以及常量通道；Q16 权重在该轴上望远镜相消，预计算结果与普通四面体逐级舍入完全一致。常量路径也必须由全部节点证明。

节点路径要求三个轴在所有可能输入上都只取 Q16 0/65536。这个条件可以由该表全域轴表直接证明，或由前一级完整节点输出上界证明；后一种条件仅对该特定四级链有效，不写成单表的全域标志。AVX2 直接计算端点节点索引，读取一个 RGB 节点。其他情况调用原有通用 Q16 算术，末尾不足 8 像素使用已验证标量运算。

四级顺序和各级整数输出保留，没有把四表复合成一表。准备、分配和证明发生在并行像素循环之前。缓存按不可变模型持有，并由 `SparseLut::prepare()` 与原有打包表一起失效；读者不能与模型编辑并发。

## 一次集中验收

| 构建 | 实际结果 |
| --- | --- |
| GCC 15.2、AVX2、OpenMP、C99 | 完整 C++ 64 位独立参考门禁通过；两个新内核可用 |
| 同编译器，关闭 AVX2 与 OpenMP，启用 C99 | 完整参考门禁通过；默认标量，C99 仍可用 |
| 同编译器，关闭 C99、AVX2、OpenMP | 编译通过；能力列表及实际调用均明确拒绝 C99 |

完整参考门禁覆盖随机与非均匀网格、四张不同模型和混合 m、1/4 线程、非连续批次、短尾、未对齐与保护字节；新增一条同时经过曲线、全域节点、前缀节点、通用插值的完整 256³ 对照，以及常量广播、缓存失效和错误前拒绝检查。每个配置只执行一次完整门禁，没有逐次修改反复跑。

四组真实模型：历史 clip/m17、历史 stress/m33、新 lookahead stress/m33、新 17 箱控制/m17。每组均由两个新内核穷举 16,777,216 个输入，与之前冻结的原生输出 SHA256 相同；另有一次无 SIMD/无 OpenMP 的新压力模型完整命令行核对，共 9 个真实完整输出流。

新压力模型的每个新内核还实际执行 100 张合成图和 5 张自然照片，输出与 R34 资格结果一致。自然照片逐字节核对完整域查表输出，统计也与 R34 相同。独立 C99 核心源码及头文件未改变，保留 R30/R31 的移植证明；本轮没有新增实体 ARM、NEON 或手机速度证明。

## 模型内存如实计入

桌面桥接为现有 `SparseLut` 拷贝一份小型 SLUT 字节流，让未修改的 C99 接口借用它。这个兼容成本只存在于桌面包装层；嵌入式调用者可以直接借用 ROM 中的序列化模型。

新压力 m33 四表的实际原生 `plan`：

| 指标 | 字节 |
| --- | ---: |
| 四张原始 RGB 节点负载 | 431,244 |
| 桥接持有的序列化副本 | 448,252 |
| 四个 C99 准备对象及一个链对象 | 12,560 |
| C99 桌面模型总运行内存估计 | 921,944 |
| 结构 AVX2 桌面模型总运行内存估计 | 1,509,320 |

最后两项包括原有模型及实际物化缓存，不能再把前面的准备对象重复相加。它们不是进程 RSS，未包括图像、分块描述、线程栈或分配器开销。两个新内核均不需要每线程像素块中间缓冲。嵌入式直接 ROM 路线与桌面兼容路线的内存口径分别报告。
