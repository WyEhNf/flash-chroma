# R21：边界完整采样与加权稀疏矩阵组装

日期：2026-10-15。继续串行工作，未推送。新方法保持四张独立RGB8节点表和原Q16逐级整数执行规则；新增的是离线拟合策略，不增加运行时表或额外映射。

## 从热点和采样覆盖出发

R20发现，`clip-7/m33`第二级在输入`[0,175,169]`上应输出`[0,223,216]`，旧分层LS却输出`[0,233,208]`。重新检查其实际Q16设计矩阵：262,144个训练点中只有6,001个在输入边界；35,937个节点中有580个数据项对角为零，边界节点也存在零支持。正则化使CG可以收敛，却不能把求解收敛等同于拟合准确。

新候选`ls_tetra_boundary`将输入颜色划分为：

- 内部`1..254`：原64³个宽度4小块各取一个内部整数颜色，权重为该块内部颜色数除以64；首尾小块对应轴宽度为3。
- 边界：精确包含所有`256³−254³ = 390,152`个颜色，每个权重为1/64。R面包含边和角，G面排除R端点，B面再排除G端点，保证无重复。

合计652,296点，总权重严格为262,144。内部取样的期望对应其全部颜色，边界是精确求和，故目标仍是均匀全色域平方误差，没有额外提高边界的目标权重。DP、CG正则参数和四轮整数二次目标精化保持原值。

DP轴节点都是整数。对于边界上的每个网格节点，新采样包含其实际整数输入，提供一个权重1/64的单节点观测。这能消除这些节点的零支持；不保证内部全有支持，也不保证最终四级最大误差下降。m33第二级的数据项零对角节点从580降至257，仍有内部节点欠约束。

## 同样的数学目标，减少组装开销

原`normal_equations`为每个样本展开16个节点对，再构造COO矩阵。新实现直接存储每行最多四项的CSR设计矩阵`A`，复用`AᵀW`，得到`H=AᵀWA`和`b=AᵀWy`。系统缓存最多两组，采样缓存只保留一组；没有把大型训练数据带入运行时模型。

冻结`clip-7/m33`第二级及同一652,296点，先核对两种组装结果：**H、b逐项精确相同**，后续求解及整数精化得到的节点字节也与已验收模型相同。随后执行7对AB/BA交替测量，每次独立启动进程：

| 项目 | 16对COO展开 | CSR设计矩阵 |
|---|---:|---:|
| H/b组装中位时间 | 391.365 ms | 139.534 ms |
| 宿主进程峰值工作集中位数 | 489,689,088 B | 227,594,240 B |

配对加速比中位数**2.775×**，bootstrap 95%区间2.723–2.931，7/7对更快。计时包含基函数及H/b组装，排除加载、生成样本、CG与整数精化；内存是整个子进程的OS峰值工作集，不能当作矩阵独占内存。这也不是图片映射速度或完整拟合流程的2.775倍加速。

七组全色mean都下降，其中m33改善约14.17%；五组全色max上升。原先的m33第二级热点现在输出恰为`[0,223,216]`，但该点修复没有转化为整链最大误差改善。单图均值也并非全部改善：`clip-7/m18`最差单图mean从1.826548升至1.853361。`clip-7/m17`和新`clip-23/m18`仍未通过示例“每图mean<2且全色mean<2”；后者新模型最差单图mean为2.080796。

## 使用与复现

```powershell
python -m lutlab fit --inputs lut1.lut256 lut2.lut256 lut3.lut256 lut4.lut256 `
  --model-dir models/my-boundary --m 18 --grid dp --method ls_tetra_boundary
```

`select --profiles dp_boundary`同样可用。manifest记录样本数、种子、实际权重、全部拟合源码与依赖版本；更改方法或源码不会命中旧缓存。
